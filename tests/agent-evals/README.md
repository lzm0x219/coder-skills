# 独立代理任务评测

这组案例补充固定夹具检查：执行代理只收到原始任务、材料和 Skill，评估方先固定预期，再检查实际产物。首轮五类任务的首次交付均满足本轮验收；未给执行代理标准答案或定向修复建议。结果只覆盖下表案例，详细证据以 run.json 为准。

| Skill | 原始任务与核验对象 |
| --- | --- |
| master | 五个目标路由：差异审查、契约设计、重构、只读诊断、新功能；核对选择和仅推荐范围。 |
| fix-bugs | 临时网关失败后任务丢失；核对原红灯、重试、异常、快照、同 key 后继和未改弱的原测试。 |
| refactor-code | 拆分账单与通知职责；核对当前用户编辑、公开形状、错误/副作用、订阅取消与关闭。 |
| review-changes | 固定两个提交；预期两处回归、成立的路径保护及不可验证的 broker 合同。 |
| design-apis | 新订单 API；核对幂等、租户、异步结果、外部效果未知、可解析契约与可检查消费者。 |

本轮实际核验：master 五项路由匹配；fix 原红灯转绿及七个公开/新增检查通过，另通过隐藏行为检查；refactor 隐藏兼容与消费者通过，用户编辑保留；review 两处预期回归检出、成立保护未误报、broker 缺口明确；API 25 组自造调用向量和 280 项校验通过，另通过独立 OpenAPI/九输入拒绝检查。这些数量不是独立任务样本数。

审查报告约 2.6 万字符，记录偏长；作为使用负担观察保留，未事后改变预定行为验收。原始红灯和取消回归负控制均保留。

## 边界轮：交付去重与受阻任务

优化仅改两处共享交付规则：审查正文引用完整证据记录，API 追踪表复用出处、证据和边界 ID；对象/逐规则状态、原始失败及要求强度继续保留。四个新上下文代理首次产物满足执行前固定的有限验收，评估方未反馈标准答案或指导修正。

| Skill | 新任务与实际结果 |
| --- | --- |
| fix-bugs | 生产负总额缺输入，复现入口缺桥接依赖；保持 S1 未完成，启动失败不冒充原症状红灯，本地通过不冒充修复。 |
| refactor-code | 只读分析，历史 CNY 与当前 USD 合同不相容；保留用户编辑和旧失败，仅交付方案，不称重构或线上兼容已完成。 |
| review-changes | 六对象混合材料；确认 stdout 唯一回归，成立路径保护未误报，vendor 与视觉事实缺口保留。正文 1,662 字符，完整命令/输出及逐规则状态在原证据载体中。 |
| design-apis | 本地 TypeScript SDK 演进；旧 list 与新 iterate 消费者编译通过，评估方三个独立类型反例被拒。同步拒绝、惰性、输入借用和关闭是有界候选，未实现、未运行或获批。 |

[edge-cases.json](edge-cases.json)保存执行前固定的输入与验收，[edge-run.json](edge-run.json)保存实际派发提示、Skill SHA、首次产物及评估方检查。沿用同一检查器，未增加逐步报告文件。脚本只检查输入保全、真实行为对照和类型；报告语义、规则状态与引用由评估方另核对，Jev 支持本轮有限验收。

SDK 追踪表共享 S/E/L 定义，各规则保留独立状态；七个未触发项的等级需通过 scope 与原 ID 回查。SDK 首次报告写“未联网”，但其证据包含 Jev 外部判断服务，因此该措辞不作为无网络活动证明。首轮与本轮任务和提示不同，没有同输入 A/B 或无 Skill 对照；篇幅观察不能换算为 token 节省或 Skill 效果。

从仓库根重放本轮保留产物：

```sh
rtk proxy env PYTHONDONTWRITEBYTECODE=1 python3 tests/agent-evals/verify.py --edge --replay --tsc <TypeScript-5.6.3编译器路径>
```

对尚在的执行目录检查时使用 `--edge <执行根目录> tests/agent-evals/edge-cases.json --tsc <编译器路径>`。重放已通过，并拒绝了临时副本中的输入字节变化及候选声明篡改；检查产物 SHA，不启动代理，不验证 SDK 的运行语义。现有 35 项审查、6 项修复工具检查、协议检查和首轮产物重放通过；同页锚点曾被链接扫描器误识别为目录，修正后通过，首次失败保留在边界轮记录。

## 输入、证据与检查

- [cases.json](cases.json)：原始材料、执行前工作区与预先固定的验收要求。
- [run.json](run.json)：Skill 文件 SHA、上下文隔离方式、首次产物、原始失败及实际检查；相同原始文件只存输入与 hash，产物存改动。
- [verify.py](verify.py)：隐藏行为、路由与 OpenAPI 输入反例检查。报告语义及结构收益仍需评估方核对，脚本不启动代理，也不以重放替代新执行。

执行目录含五个角色子目录时，从仓库根检查：

```sh
rtk proxy env PYTHONDONTWRITEBYTECODE=1 python3 tests/agent-evals/verify.py <执行根目录> tests/agent-evals/cases.json --api-python <验证环境的Python>
```

`--api-python` 需要 `openapi-spec-validator` 和 `jsonschema`。使用 `--replay` 可在临时目录重建保留产物并重新运行上述检查；它复核本轮产物，不重新测量代理能力。

## 适用限制

五个执行代理均使用无父任务历史的新上下文；各自只获指定 Skill 与临时材料，预期由评估方隔离。文件访问隔离依靠指令，使用同一文件系统与模型体系，未作操作系统强制隔离。master 的五项提示共用一次新上下文。输入是评估方构造的合成任务，没有无 Skill 对照、不同模型对照或外部真实 PR 样本。通过只覆盖本轮案例，不推定生产可靠性、安装发现效果或全规则正确率。
