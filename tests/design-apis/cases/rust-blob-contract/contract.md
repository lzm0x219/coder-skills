# Rust 读取扩展接口：跨语言交付验证

状态：**可供设计评审，尚未获设计接受**。这是一项框架扩展能力，不设计完整存储 SDK 或具体后端。主契约为 [`src/lib.rs`](src/lib.rs)，调用方示例为 [`examples/consumer.rs`](examples/consumer.rs)；Cargo 1.98.1 的 `cargo check --examples` 已通过。编译不表示已有存储实现或运行行为。

## 模型与名称

- E1 是调用方给出的不透明键；空键非法，键的进一步格式由具体实现约定。
- E2 是可能存在的对象；合法键未找到时返回 `None`，与打开失败区分。
- E3 是取得所有权的读取句柄；读取可再次失败，丢弃句柄释放资源。
- `BlobStore.open` 表示取得待消费句柄，避免 `download` 暗示内容已经完整下载。`BlobStore` 是本提案的设计取舍，备选 `ObjectReader` 会误把单个读句柄与可查找多个对象的提供者混同。未来公开名称须由目标框架调用方确认。

## 公开契约

`BlobStore` 是面向第三方实现的稳定 trait 候选；实现者须可在多个线程中被共享，`open` 可能阻塞。一次 `open` 只为一个键取得一个句柄；本接口不提供分页、写入、缓存或远程取消。成功的 `Some` 把拥有的 `Read + Send` 句柄交给调用方，调用方消费后通过 drop 释放；`None` 仅表示对象不存在。`OpenError::InvalidKey` 在产生 I/O 前返回；`Backend` 表示提供者失败，可能已发起 I/O，不能解释成不存在。读取期间的错误由 `Read` 返回，示例将它与打开错误分开。

本接口没有隐式重试；调用方重试 `open` 会重新尝试取得句柄，而重复读取同一键不保证内容快照一致。目标场景假设 drop 不产生需要报告的清理错误；若未来实现需要可观察的关闭失败，应另设计显式结束协议，不能让 Drop 的静默失败承载保证。错误内部原因可能包含敏感信息，实际实现须在公开诊断中遮蔽秘密。

对扩展者的兼容承诺从正式发布版本开始。新增 trait 必需方法会让旧实现无法编译；未来增加能力应优先用新 trait、默认方法或新版本边界。`OpenError` 标为 `non_exhaustive`，消费者须处理未来错误成员。`examples/consumer.rs` 使用 4096 字节固定缓冲区，避免默认无界读取；它仅编译接口形状，未模拟并发、资源释放或后端错误。
