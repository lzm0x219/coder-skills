# Python 审计 SDK：跨语言交付验证

状态：**可供设计评审，尚未获设计接受**。这是虚构服务，以下服务行为均为演练假设，不代表真实提供者。主契约为 [`audit_sdk/__init__.pyi`](audit_sdk/__init__.pyi)，正常与限流调用见 [`consumer.py`](consumer.py)；[`pyrightconfig.json`](pyrightconfig.json) 固定检查范围与 Python 3.12 目标。Pyright 1.1.414 严格检查通过（0 errors、0 warnings）；没有运行时实现，不能导入执行或访问远端服务。

## 中性模型和命名

- E1：一次按创建时间倒序读取的审计事件；有服务端事件 ID、类别和 UTC 时间。
- E2：一次网络请求得到的最多一页事件及不透明继续游标；未承诺跨页快照一致。
- E3：持有凭据与连接资源的客户端；调用方负责用 `with` 或 `close()` 结束使用。
- `EventPage` 表明单页；`list_page` 明确一次调用只发一次请求。`events`/`records` 都可能表示 E1；本演练由设计者选 `Event`，因为调用方围绕发生过的动作读取审计流。这是**提案取舍**，不是外部标准唯一推出的名称。

本提案的公开入口仅为 `audit_sdk` 模块中的 `AuditClient`、`AuditError`、`Event`、`EventPage` 和错误码类型；目前没有已发布版本或旧消费者。拟议 v1 接受新的未知 `Event.kind` 字符串，不把它固定成封闭枚举。

## 操作语义

| 入口 | 成功与可见副作用 | 失败与恢复 |
| --- | --- | --- |
| `AuditClient(...)` | 要求 HTTPS `endpoint`、非空 `token`、正有限 `timeout_seconds`；默认 10 秒。仅保存配置并创建可用客户端；是否懒连接由实现决定，但首次 `list_page` 可发生网络 I/O。 | 本地非法输入抛 `AuditError(code="invalid_input", operation="open")`。凭据由调用方传入并持有；实例创建后不跟随外部变量更改。 |
| `list_page(...)` | 每次调用最多一次读取请求，`page_size` 默认 50、范围 1..100；`cursor=None` 表示首页，返回 `EventPage`。末页 `next_cursor=None`，游标不透明；不同页可能有重复或缺口。 | 参数非法在网络前报 `invalid_input`；鉴权失败为 `unauthorized`；限流为 `rate_limited`，可带非负秒数的 `retry_after_seconds`；未收到响应为 `transport_failure`。默认无自动重试，调用方决定是否按建议时间重试。 |
| `close()` / `with` | 释放客户端持有的连接；重复关闭安全，关闭后 `list_page` 报 `invalid_input`。`__exit__` 不吞掉调用者异常。 | 此演练假设关闭自身不会失败；若实现不能兑现，必须修改公开契约后再实现。 |

`Event.created_at` 是带 UTC 时区的 `datetime`；`EventPage.items` 是不可变快照。`AuditError` 的 `code` 是稳定机器类别，消息不包含 token。客户端可被多个线程共享但同一方法调用不会修改其他调用的页状态；本演练不设计流、批量或远端写操作。

客户端只有显式构造参数这一种配置来源，**不读取环境变量或配置文件**。本层持有并关闭自己的连接；v1 不接受自定义代理、传输或重试策略。`token` 固定在客户端创建时，轮换须重建客户端；要求凭据具备假设的 `audit.read` 权限。单次 `list_page` 的超时预算包含凭据使用、连接和完整响应接收，默认 10 秒；跨多页没有隐藏的总预算。仅有一次网络尝试，失败后调用方决定是否再读；因为页间没有快照保证，重读或继续读取可能见到不同集合。构造、请求和关闭不暴露 token 到日志、异常或默认对象表示。

此演练假设游标在取得后 1 小时内可由新客户端继续，`None` 是唯一的终止标志；过期、空字符串或非法游标为 `invalid_input`，不静默返回首页。服务不提供同一列表的快照保证。服务版本固定为假设的 `2026-09-30`；真实 SDK 需在服务契约确认后重新决定版本支持范围。没有响应请求 ID、限流配额或原始响应的公共访问入口；若诊断需要这些信息，应先修改提案。

本地输入错误先于网络；收到服务拒绝时保留 `unauthorized` 或 `rate_limited`；未收到可判定响应时返回 `transport_failure`，不把读取失败说成空页。`close()` 完成后再调用 `list_page` 报 `invalid_input`，不会发网络请求。`with` 的退出始终调用 `close()`，不吞掉主体异常。本演练假设关闭不失败；这是实现前需验证的显式假设。
