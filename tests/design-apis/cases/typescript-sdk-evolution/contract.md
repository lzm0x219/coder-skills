# TypeScript SDK 参数演进：旧消费者回归

状态：**可供兼容性设计评审，尚未获设计接受**。本例固定[旧消费者](old-consumer.ts)，把同一个拟议包导入路径 `@example/search` 分别映射到[已发布 v1 演练声明](v1.api.ts)和[候选 v2 声明](candidate.api.ts)；[旧版配置](tsconfig.v1.json)与[候选配置](tsconfig.candidate.json)记录映射。TypeScript 5.6.3 严格检查在两套配置下均通过。`@example/search` 是测试用候选包名，没有真实发布包；类型检查不能证明安装后的 `exports`、运行行为或 ABI。

## 已知契约与变更动机

演练前提：v1 `listPage({ limit, cursor })` 每次只取一页；`limit` 默认 50，范围 1..100，`nextCursor` 缺失表示末页。它已经公开给旧消费者，改变 `limit`、默认值、返回类型、错误码或页序均是潜在破坏性变更。v2 希望让参数在调用点更明确，新增 `pageSize`。这是产品设计取舍；行业规范并未要求把已有 `limit` 改名。

## 候选兼容契约

- v2 保留 `limit` 的原含义、默认值与范围，只添加 `pageSize` 作为同义参数；两者都缺失时仍为 50。
- 同时提供 `limit` 与 `pageSize` 时，在发请求前以 `invalid_input` 拒绝，避免隐式优先级；旧的合法调用不会遇到此组合。
- 新调用推荐 `pageSize`；旧参数继续受支持，本提案**未启动正式弃用**。若决定弃用或移除，须先给替代、迁移示例、告警方式、最早移除时点及发布政策，再按兼容性规则评审。
- 返回页的字段、空值与顺序承诺不变；错误码集合不变。真实服务是否仍满足旧分页语义、限流和鉴权行为，需通过实现和旧消费者运行测试验证。

## 核验范围

`old-consumer.ts` 的源码在两套检查中保持不变；`new-consumer.ts` 只对候选声明检查。两套严格类型检查均通过时，仅证明这组消费者在 TypeScript 源码层面仍可编译。[负对照声明](broken.api.ts)与[负对照配置](tsconfig.broken.json)移除 `limit`；TypeScript 5.6.3 检查按预期以 `TS2353` 失败，说明这组检查能发现本次要防止的源码破坏。行为兼容、真实包导出、序列化形式、支持环境和发布级别均不能由此推出。项目若使用 SemVer，最终发布级别须按其正式公共 API 政策与运行验证决定。
