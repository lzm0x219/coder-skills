# 运行可靠性

容量概念参考 [SRE](../sources.md)；预算与承诺取自项目。

<a id="q1"></a>

## Q1 背压与过载

触发：生产/消费队列、缓冲、并发限制或限流变化。

必须明确容量、进入/退出速率和过载时阻塞、拒绝、丢弃或持久化的契约；检查队满、消费者停顿、重试放大及恢复后的积压。资源成本按 [R2](resources.md#r2)、[R3](resources.md#r3)。

完成：过载有可达且有界的行为，或能证明积压无界/违反允许损失范围。不能只看 queue 类型是否有 maxsize；入口旁路、隐藏缓冲和全局规模同样要核实。

<a id="q2"></a>

## Q2 消息提交、确认与重放

触发：ack/nack、offset、投递、消费者幂等或死信变化。

必须按真实 broker/协议核实持久化、副作用、提交与确认顺序；检查提交前失败、提交后确认丢失、毒消息、重复及乱序，追踪业务身份。重试复用 [A3](async.md#a3)，去重复用 [D5](state.md#d5)。

完成：交付语义及允许丢失/重复有证据。内存模拟仅证明所建窗口，不能证明真实 broker exactly-once；明确 at-most-once 允许损失时不得强制改为其他语义。

<a id="q3"></a>

## Q3 锁顺序与活性

触发：嵌套锁、等待、条件变量、同步回调或跨进程租约。

必须列实际可达的获取/等待顺序，查等待环、释放、超时后的状态及唤醒条件；租约过期还查旧持有者是否能继续写入和 fencing/version 检查。

完成：活性有依据，或给出双方路径及可达等待环。只有锁顺序不同而路径互斥时不确认死锁；timeout 不自动撤销已有副作用或旧所有权。

<a id="q4"></a>

## Q4 分区、切换与恢复

触发：leader、复制、读写路由、故障切换、恢复或备份变化。

必须依据一致性和 RPO/RTO 来源核实断连、旧 leader、切换窗口、恢复点及外部依赖故障；检查恢复流程与数据格式/权限。无需真实故障的源码结论与演练证据分开。

完成：改变路径满足声明恢复/一致性条件或有具体破坏窗口。存在备份不证明可恢复；缺恢复演练不直接等于已发生数据损失。

<a id="q5"></a>

## Q5 时钟与期限

触发：deadline、TTL、租约、定时器或跨机器时间比较。

必须区分持续时间与日历时间，检查单位、时钟倒退/漂移、期限传播及剩余预算；本地 elapsed-time 需要的单调性查实际 API。业务日期按 [V2](semantics.md#v2)。

完成：目标语义在允许的时钟条件下成立。不能无依据要求所有时间都换成 UTC 或 monotonic；单调时钟值不能当跨进程共享时间戳。
