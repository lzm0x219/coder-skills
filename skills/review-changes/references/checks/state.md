# 状态与存储

必须使用项目真实存储语义；内存模型只能证明所模拟的路径，不能冒充真实数据库隔离或性能结论。

<a id="d1"></a>

## D1 缓存键、命中与失效

触发：缓存键、缓存内容、TTL、读写顺序或失效变化。

必须列出能改变结果的实际维度：租户、用户/权限、查询参数或数据版本；核实哪些已进入键或在命中后重新校验。追踪写入后相关缓存如何失效，以及失败/空结果是否被缓存为有效成功。

完成：两个结果本应不同的可达请求不会误共用内容，更新后的可见性符合时效契约。明确为公共且结果相同的数据不需强加用户维度；不能只凭键里没有 tenant 就报跨租户问题。

<a id="d2"></a>

## D2 原子性与外部副作用

触发：一次操作内多次写入、事务边界或提交前后通知变化。

必须列出同一不变量依赖的写入，选取第一项已成功而后一项失败的窗口，核实实际回滚范围；外部通知/消息不在本地事务内时须单独追踪其提交和恢复语义。

完成：失败后的可见状态满足不变量，或有明确且可达的补偿/恢复路径。不能用“有 transaction”推定外部邮件、队列或另一连接的写入也会回滚；outbox 等机制应按真实消费者核实，不要求固定架构。

<a id="d3"></a>

## D3 读改写与条件约束

触发：先读再更新、配额检查、库存扣减、版本号或写入谓词变化。

必须核实条件是否与写入原子绑定，查实际事务隔离、锁范围或版本条件；构造两个调用都读到相同旧值再更新的序列，检查丢失更新、负库存及重复满足限额。

完成：关键不变量在可达并发下有存储保证，或有可复核违反序列。隔离级别/锁作用域不明时标未验证；不能把进程内锁当跨实例保护，不能把普通读事务当排他写锁。

<a id="d4"></a>

## D4 数据迁移与兼容期

触发：字段新增/改型/删除、回填、索引或旧路径退役。

必须读取旧数据样例与新旧读写入口，沿项目实际切换顺序检查旧数据→新代码、混合运行、回填重跑及中断恢复；删除字段前核实剩余消费者。仅在声明支持回退时检查回退所需旧数据是否仍存在。

完成：每个受支持阶段有可读取状态与恢复依据，未完成回填的值不会被当合法新数据。不能用新建空库测试证明生产旧数据可迁移；明确停机且无需混合运行的迁移不强加双写。

<a id="d5"></a>

## D5 去重身份与唯一性

触发：upsert、唯一键、重复消息去重或幂等记录变化。

必须确定唯一性属于哪个业务操作、租户和时间窗口；检查同操作重放与不同操作同键两种情况，核实去重记录和业务提交的先后关系。变化涉及请求重试时必须读取 [A3 重试与未知完成状态](async.md#a3)。

完成：同操作不会重复产生契约禁止的副作用，不同合法操作不会被错误吞掉；提交失败不会留下永久“已完成”的去重标记。不能将“发现同键”直接解释为“之前已成功”。

<a id="d6"></a>

## D6 查询规模与资源预算

触发：循环内查询、全量加载、查询谓词/索引或批量大小变化。

必须确定实际数据规模、单次/多次调用关系和项目预算；计算或观测请求数、传输/内存量及扫描范围。新增筛选须查真实执行计划或索引适用条件，不能仅凭有索引名判查询受索引保护。

完成：资源代价在明确规模和预算下有结论，或记录缺少的规模/计划证据。代码能证明每行发一次远程请求时可报告该成本；只有证明违反实际约束才定为性能缺陷，不能从新增循环外观推定线上变慢。
