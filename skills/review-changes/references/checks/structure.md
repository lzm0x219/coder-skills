# 结构与语言

按实际编译器、配置和官方资料核实语言前提，参考入口见 [来源](../sources.md)。

<a id="m1"></a>

## M1 依赖方向与初始化

触发：新增模块依赖、移动职责、循环导入、注册或初始化副作用。

必须追踪实际加载顺序、依赖图和公开/内部边界；核实是否出现部分初始化、重复注册、平台不支持依赖或违反项目明确的分层规则。

完成：新路径能加载且依赖方向有依据，或有具体失效/适用标准。不能仅凭循环或层数指控运行缺陷；工具已强制的规则引用实际检查结果。

<a id="m2"></a>

## M2 状态归属与不变量

触发：共享可变对象、复制/别名、领域状态分散、新增抽象，或改变设计复杂度、命名与注释。

必须追踪每个写入者和所有权，检查同一业务规则各副本是否仍一致；比较调用方为完成一个操作必须了解的内部细节。并发写入按 [A2](async.md#a2)，持久化按 [D2](state.md#d2)、[D3](state.md#d3)。

必须结合真实调用、修改或排错任务核实新增复杂度：调用者是否要记住隐藏顺序，规则是否要在多处同步修改，命名/注释是否误导合法用法，抽象是否增加当前需求不需要的配置或分支。没有状态写入的对象仍检查其设计与可理解性，不强行寻找写入者。

必须核对该路径适用的项目命名、注释和风格要求；已由工具检查的项复用实际结果。工程原则可支持维护风险分析，不能冒充项目明文规范。等价方案有数据或工程依据时保留作者选择，不因个人偏好要求改写。

完成：受影响写入有所有者和约束，设计评价由具体违反规则或真实维护任务支撑。代码气味只能作为调查线索或获请求的建议，不强制一律提取、拆分或套用设计模式；行数、嵌套层数或抽象数量本身不能证明缺陷。

<a id="m3"></a>

## M3 类型与动态边界

触发：断言、any/动态类型、反射、枚举扩展、可空值或不安全转换。

必须找到值的真实来源及运行时校验，核实新类型是否能表达非法状态、调用方是否穷尽有效分支，使用项目真实类型配置检查。外部输入的静态声明不能替代验证。

完成：有效值与拒绝值到消费者有证据；断言若已有不可绕过保护则是反证。不能因编译通过推定 JSON 有效，也不能把所有断言当缺陷。

<a id="m4"></a>

## M4 内存、生命周期与未定义行为

触发：裸指针、借用/别名、unsafe、手工分配、缓冲区、跨线程对象或内存布局。

必须依据语言内存模型核实有效期、边界、对齐、初始化、整数运算前提及同步；查所有提前退出与转移所有权。用匹配工具链的 sanitizer/检查器仅验证其能覆盖的路径。

完成：改变的安全前提有来源及可达证明，或标出违反前提的路径。普通测试未崩溃不是无未定义行为证明；GC 也不证明跨线程对象、原生扩展或悬挂资源安全。

<a id="m5"></a>

## M5 FFI 与跨语言表示

触发：绑定、ABI、回调、跨语言对象/错误/线程调用。

必须核实双方版本、调用约定、宽度/布局、字符串编码、缓冲区长度和释放者；回调保活、线程约束与错误越界有真实路径。公开兼容另按 [C1](contracts.md#c1)、[C2](contracts.md#c2)。

完成：边界两侧实际声明一致并有针对性证据；仅一侧编译或主机架构测试不足覆盖支持的其他 ABI。缺外部库或目标架构时明确缺口。
