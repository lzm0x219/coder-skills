# 资源预算

数据库特定查询按 [D6](state.md#d6) 核验。

<a id="r1"></a>

## R1 算法增长与真实工作量

触发：遍历/嵌套、排序、递归、搜索或重复计算改变。

必须定义实际输入规模及允许上限，估算最坏和常见工作量，追踪攻击者或业务如何达到它；与预算/基线比较，必要时使用相同输入、环境与预热方式测量。

完成：增长和可达规模足以判断预算，或保留容量缺口。不能仅凭双循环宣布性能缺陷，不能用小样本耗时外推全规模；有硬上限且满足预算是反证。

<a id="r2"></a>

## R2 内存、流与保留

触发：全量读取、缓存、闭包保留、复制、解压、批量或递归栈改变。

必须追踪峰值活跃数据、释放点和输入放大；检查流式接口是否内部仍聚合、失败/取消是否释放以及多个并发任务的总量。资源释放按 [A5](async.md#a5)。

完成：峰值有界且符合环境预算，或有具体超额/泄漏路径。单个请求限制不能证明进程总量有界；合法限量且及时释放的缓存不是泄漏。

<a id="r3"></a>

## R3 并发配额与公平性

触发：线程池、连接池、任务扇出、令牌/速率限制或共享额度。

必须查额度作用域、排队上限、单用户占用、饥饿与释放失败；区分每实例和全局限制。队列行为按 [Q1](reliability.md#q1)，租户隔离按 [T2](trust.md#t2)。

完成：最大在途量和公平承诺有依据，或可达耗尽/饥饿证据。不能用线程安全推定吞吐或公平，也不能没有服务承诺强制公平调度。

<a id="r4"></a>

## R4 计费与工作放大

触发：网络下载、模型调用、轮询、外部 API 或收费存储的重复/扇出。

必须确定一次业务操作的调用量、输出/输入限制及失败重试乘数，检查预算在哪里强制以及用户是否能绕过；实际费用采用项目价格/配额资料。

完成：放大可估算且受声明预算限制，或具体超额路径成立。不能以当前价格推定历史成本，不为验证而产生未授权收费。
