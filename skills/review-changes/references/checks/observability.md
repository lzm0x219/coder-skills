# 可观察性

敏感出口按 [T4](trust.md#t4) 核验，监测概念参考 [来源](../sources.md)。

<a id="o1"></a>

## O1 信号语义与可诊断性

触发：错误记录、统计口径、trace 关联或日志等级变化。

必须核实成功/失败/取消各分支如何记录，分母、单位、计数点与重试是否重复计数；关联 ID 应能追踪实际操作，异步边界传播有证据。

完成：重要路径的信号反映实际结果，或明确误导/缺失后果。不能强制每个函数打日志；项目有其他可靠信号是反证，日志缺失无影响依据仅列覆盖缺口。

<a id="o2"></a>

## O2 标签、采样与监测成本

触发：新增标签、用户/请求维度、采样或指标聚合。

必须估算标签组合和输入控制范围，检查采样是否丢失承诺检测的事件、低流量分母和指标溢出；监测自身的队列/成本按 [R2](resources.md#r2)、[R4](resources.md#r4)。

完成：基数和检测口径有依据，或有实际无界/误报/漏报路径。不能一概禁止高基数日志字段；指标标签与日志查询成本分别核实。

<a id="o3"></a>

## O3 探针、报警与运维动作

触发：health/readiness/liveness、报警阈值、runbook 或自动恢复。

必须追踪探针失败触发什么动作，区分暂不接流量与进程重启；依赖故障、启动窗口、故障风暴和恢复后阈值清除都须核实。

完成：信号到操作的链条与服务承诺一致。healthy 响应不证明业务正确；把外部依赖失败直接变为 liveness 重启可能需要可达风暴证据才能确认。
