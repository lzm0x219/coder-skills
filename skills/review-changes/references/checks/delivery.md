# 构建与验证

实际命令和文件位置从当前项目查，不能用固定工具链替代项目事实。

<a id="l1"></a>

## L1 实际执行入口

触发：脚本、CI job、构建配置、启动命令或生成器变化。

必须从用户/CI/发布的实际入口追到被修改步骤，核实工作目录、执行条件、依赖顺序和退出码传播；尤其检查新脚本是否被调用、失败是否被管道/条件吞掉。

完成：目标路径确实执行新逻辑且失败能被负责入口观察，或给出未接线/吞错证据。手工运行脚本成功不能证明 CI 会运行它；入口来源不可访问时标未验证。

<a id="l2"></a>

## L2 配置来源与环境差异

触发：环境变量、默认配置、加载顺序、路径或开关变化。

必须确认配置来源的优先级、读取时机和失败行为；分别查省略值、显式值和无效值的改变路径。声明支持多个环境时对照部署实际注入方式，检查 build-time 值是否误当 runtime 可变值。

完成：受支持入口取得预期值或给出具体偏差。配置解析改变缺失/真假值或数值范围时必须读取 [B1](behavior.md#b1)、[B2](behavior.md#b2)。不能只凭本地已设置变量证明无变量的部署能启动，也不能替用户规定未承诺的配置策略。

<a id="l3"></a>

## L3 分发与干净消费者

触发：exports、打包白名单、资源路径、生成产物或安装方式变化。

必须从发布入口核实实际包含文件、导出路径及运行时需要的资源/依赖；生成源改动要核对交付产物的一致性。需要运行验证时用隔离、干净消费者而非仓库内部相对导入。

消费者必须使用契约承诺的导入形态。包名导入、包子路径和绝对文件/目录路径须分开核实；例如直接加载目录可能走 main，不能用其成功证明包名导入会走 exports 并成功。

完成：受支持的导入/安装/启动路径在交付形态可解析，或有缺文件/错误导出的依据。源码可运行不能代替安装包可运行；本机旧 dist 和全局依赖不能补足缺失产物。

<a id="l4"></a>

## L4 发布切换与混合版本

触发：部署顺序、旧路径退役、功能切换或声明的回退变化。

必须核实项目真实切换策略，追踪新旧消费者在受支持窗口读写的组合；若声明可回退，检查旧代码还需要的数据、配置和制品是否仍在。变化包含数据迁移时必须读取 [D4 数据迁移与兼容期](state.md#d4)。

完成：受支持窗口及回退承诺各有可执行依赖顺序，或有具体失效组合。明确停机且不承诺混合版本时按该策略检查，不能强加滚动发布或任意回退要求。

<a id="l5"></a>

## L5 测试信号与验证失效

触发：生产行为变化，或测试、fixture、mock、断言、快照、检查开关变化；也适用于用现有测试支持本次结论。

必须按受影响行为、失败风险及项目验收门槛判断验证是否足够，选择能观察该风险的单元、集成、端到端检查或充分源码证明。没有测试文件改动也要检查现有证据能否覆盖新行为；不能机械要求每次改动新增测试或运行全部测试。

必须确认测试真正进入受影响路径并观察契约行为；新增/改动测试须说明目标失败会怎样被它捕捉。检查 mock 是否绕过问题、测试是否被 skip/过滤、错误是否被断言吞掉以及是否有实际执行结果。

完成：相关检查有运行结果与所证明行为，或明确的未运行/未覆盖项。缺测试或未运行本身记为验证缺口；只有违反明确的项目验证要求时报告相应规范/需求违反，不能据此推断行为已坏。必要时用最小失败变体验证信号，不能为了做变体改用户工作区。快照文字相同、测试数增加或测试名包含需求均不能代替能捕捉错误的断言。
