# 供应链

先确定项目政策；[GitHub 安全实践及 SLSA](../sources.md) 提供参考，不自动成为本项目强制标准。

<a id="s1"></a>

## S1 来源与依赖解析

触发：依赖、注册表、锁文件、下载 URL、镜像或插件来源改变。

必须核实实际解析版本/完整性、来源变更者和执行位置；查锁定是否适用于当前工具及平台。版本行为复用 [C4](contracts.md#c4)，公开漏洞只有匹配受影响版本、配置和源码路径才称确认。

完成：引入代码的身份及解析链有证据。没有 lockfile 不自动是漏洞；固定标签也不等于不可变 digest。不能凭陌生包名宣布恶意。

<a id="s2"></a>

## S2 安装与构建执行权限

触发：install/postinstall、生成器、构建插件或下载后执行。

必须追踪执行者、可读秘密、写入目录、网络范围和信任边界；判断是否执行来自未信任提交/依赖的代码，核实沙箱限制实际生效。

完成：代码来源与权限匹配授权政策，或具体越权链成立。只下载不执行与执行脚本不同；开发机成功安装不证明 CI 的权限边界安全。

<a id="s3"></a>

## S3 CI 输入与令牌

触发：工作流事件、checkout/ref、表达式、令牌权限、OIDC 或复用 workflow。

必须把不可信 PR/文本/分支追踪到 shell、runner、凭据及产物；核实触发事件的权限，外部 action 固定方式和 repo/environment 约束。上下文转义按 [T3](trust.md#t3)。

完成：不可信输入与高权限执行之间有明确保护或可达攻击链。不能只凭 pull_request_target 名称定漏洞，必须核实是否 checkout/执行不可信内容及可得权限。

<a id="s4"></a>

## S4 制品身份与验证

触发：签名、provenance、发布、缓存复用、镜像或更新来源。

必须追踪预期制品到实际下载/部署字节、构建来源及校验者信任根；查校验失败处理、缓存键和可修改元数据。打包内容复用 [L3](delivery.md#l3)。

完成：来源和完整性保证达到项目声明等级，或存在实际替换/绕过。hash 若来自同一可替换渠道不独立证明身份；存在签名文件不代表消费者验证。不能声称未经正式核验的 SLSA 等级。
