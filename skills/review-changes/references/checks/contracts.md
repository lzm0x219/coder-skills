# 契约与消费者

<a id="c1"></a>

## C1 签名与实际调用

触发：参数、返回值、同步/异步形态、导出符号或重载变化。

必须找出仓库内实际消费者及已声明支持的外部用法，检查位置参数、可选参数、返回值解包和生命周期假设。需要验证类型兼容时，用旧调用形态编译/检查目标版本；动态调用还须追踪实际运行结果。

完成：受影响调用形态有消费者证据或明确外部验证缺口。目标库自身能编译不能替代旧调用者能编译；已授权破坏性更新按版本/迁移承诺评判，不把所有签名变化都报成缺陷。

<a id="c2"></a>

## C2 序列化与消息读写

触发：字段名、可空性、枚举、默认值、编码、事件或协议结构变化。

必须读取生产者的真实输出和消费者的真实解析方式；分别检查缺失与显式 null、未知字段/枚举值、数字/字符串表示，限于本次受影响的形式。兼容期有旧消费者时，用目标消息检查它的行为；有旧存量消息时用新消费者检查读取。

完成：受支持方向的读写组合均有结果或缺口。类型定义相同不证明线上表示相同；不能自行假设消费者忽略未知字段，也不能用只展示必填字段的样例排除可空路径。

<a id="c3"></a>

## C3 成功、空结果与错误类别

触发：状态码、错误类型、错误字段、空结果或部分成功变化。

必须追踪消费者如何区分成功、未找到、无权限、暂时失败和永久失败，只保留本接口实际承诺的类别；核实新结果是否改变重试、缓存、UI 或退出码。变化涉及错误包装/吞错时必须读取 [B4 错误传播与降级](behavior.md#b4)。

接口承诺错误码、字段级定位或其他机器可读元数据时，必须逐字段核实改变的失败路径及消费者依赖；错误类别未变也不能跳过定位、结构或字段丢失。

完成：可达的改变类别和承诺字段有消费端后果对照。不能将空列表、404、异常当成天然等价，也不能要求接口提供其契约从未承诺的类别或字段。

<a id="c4"></a>

## C4 依赖版本与运行能力

触发：依赖/运行时版本、feature flag、导入路径或依赖 API 用法变化。

必须从项目配置、锁文件及实际运行入口确认生效版本、启用特性和安装目标；核对所用 API/参数在该组合下存在且语义相符。跨环境支持有声明时检查对应支持矩阵，不只查当前机器。

完成：实际版本下的行为或类型检查有证据，版本资料匹配；未安装的平台/特性写明缺口。不能用最新文档解释旧依赖，也不能用开发机有全局依赖证明干净安装可运行。

<a id="c5"></a>

## C5 承诺遗漏与未授权扩展

触发：本次有规格/issue 验收条件，或实现增加调用者可见行为。

必须逐项追踪承诺的操作、失败条件和范围排除项到具体入口及实现；检查不存在的实现，而不只看 diff 中写出来的部分。新增公开行为须找出授权来源及是否改变旧消费者，不把内部实现辅助函数误当新产品能力。

改变已有公开用法、构建/运行流程或弃用行为时，必须核对受影响文档和示例是否仍描述目标版本，按 [N1](../profiles/noncode.md#n1) 检查具体声明；没有文档 diff 不能跳过旧声明。是否必须新增文档由项目承诺与真实消费者需要决定，不能要求每个内部改动配一份文档。

完成：每个相关承诺被实现、确认遗漏或明确语义未定；公开扩展有授权或具体偏离证据。测试名、TODO 或文档声称“已支持”不能代替实际入口。
