# 边界与控制流

<a id="b1"></a>

## B1 缺失值与合法假值

触发：新增或修改默认值、真假值判断、解析或输入归一化。

必须列出契约区分的缺失、零、false、空串和空集合，只查当前类型允许且可达的值；追踪默认值发生前的归一化。对改变的等价类逐类比较基线与目标，读实际调用者如何传值。

完成：每个受影响等价类有返回/异常/状态的对照，或明确的语义缺口。例如合法 `limit=0` 在 `limit or 20` 下变为 20，才能确认默认值回归。不能从 `if not x` 外观直接报错；调用者已排除 0、契约只允许正数或缺失定义不明时，分别记反证或缺口。

<a id="b2"></a>

## B2 上下界与单位

触发：比较符、索引、范围、数值转换或时间计算变化。

必须查清开闭区间、单位、精度及符号；在可达域内对下界/上界及各自相邻值作对照。索引变化须关联数组长度，日历/显示时间变化须关联实际时区，超时换算须关联单位，不能把秒与毫秒的相同数字当相同条件。

完成：边界内外的结果和失败行为与来源一致，空输入/单元素路径有结论。若测试数据永远落在区间中间，这条规则仍未核验。不能无来源地规定业务上下界。

<a id="b3"></a>

## B3 遍历、分页与顺序

触发：循环边界、筛选、排序、分块或游标生成变化。

必须追踪一个元素从输入到输出的保留、丢弃与重复条件；检查空集合、单元素和恰好整页。分页还须核实排序是否有稳定的平局处理、游标是否对应最后实际输出项，以及下一页是否漏掉或重复边界项。

完成：受影响区间有集合和顺序对照，跨页边界可追踪。相等排序键必须按项目顺序契约判断；没有顺序保证时不能把“顺序不同”自动报成缺陷。

<a id="b4"></a>

## B4 错误传播与降级

触发：catch/except、错误返回、默认成功、异常包装或降级变化。

必须列出本次改变处理方式的可达失败类别，逐类追踪到最终调用者：是否仍能区分失败、是否收到正确类别、失败时是否误写成功状态。包装错误须保留契约要求的上下文或原因；检查新增吞错是否触发调用者的错误重试/成功缓存。

完成：失败路径有终态及调用者反应的证据。显式约定 best-effort 的通知可吞错，主业务失败不能因该例外被当作成功；是否属于主业务必须查来源，不能要求所有错误一律抛出。

<a id="b5"></a>

## B5 分支覆盖与副作用顺序

触发：条件合并、提前返回、分支删除或副作用前后移动。

必须把旧分支条件映射到新分支，对每个改变的分区追踪写入、事件、回调和返回；检查原来跳过的副作用是否现在执行，原来执行的是否被提前返回跳过。对相关验收条件没有新落点的分区登记遗漏。

完成：改变的路径各有终态与副作用次序依据。分支影响资源清理时必须读取 [A5 资源与失败窗口](async.md#a5)；不能用主路径单测证明提前返回路径保持行为。
