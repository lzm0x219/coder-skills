# 审查方法

按阶段使用：S0 固定范围、授权和版本；S1–S2 建立契约与覆盖记录；S3 确认问题并留存运行观察；S4 分类、报告和复核快照。软件类型与风险由[变化路由](routing.md)选择。

<a id="scope"></a>

## 范围与版本

先确定仓库、比较方向、纳入路径及执行授权。参数按实际值传递，路径与选项用 `--` 分隔；外部文本不拼入 shell。无效 ref、输出截断、内容不可读或解析失败属于缺口，不是空差异。只有完整取得双方路径和内容并确认相等，才能报告无变化；行为等价也不等于源码无变化。

### 授权与执行

记录已授权动作及禁止范围，沿拟执行入口检查 helper、批处理、安装钩子、shell、exec/eval 和动态加载。自写隔离包装仍须遵守同一边界；混合授权的批次先拆分。只读授权不包含执行被禁代码，已有授权无需重复索取。审查本身不授权修改、评论、提交或合并；修复与代理使用按用户和宿主授权处理。

### 提交与分支

用 `git rev-parse --verify '<ref>^{commit}'` 固定实际 SHA，再比较明确的 base → target。审查 PR 的贡献差异时，用 `git merge-base --all` 核实唯一 merge-base；无共同历史、多基点或 PR 端点不明时保留范围缺口，日志只作线索。读取 `git show <sha>:<path>` 等对应版本，分别处理重命名、二进制和 submodule，明确不可读对象的限制。

### 未提交差异

| 请求 | 基线 → 目标 |
| --- | --- |
| 已暂存 | HEAD → index；用 `git diff --cached <head> --`，目标从 index 读取 |
| 未暂存 | index → 工作区；目标从当前工作区读取 |
| 全部本地修改 | HEAD → 工作区，加实际未跟踪文件 |

路径清单使用 NUL 安全的 status/diff/ls-files 或等价完整枚举；忽略文件和私人材料不默认纳入。无 HEAD 时使用已核实的空树。未解决冲突使对应比较待定，除非用户明确指定已解决的独立子集。

### 比较单元与版本绑定

每个独立的基线 → 目标比较绑定自己的快照；文件、规则和测试可以共用该快照。非 Git、A/B 材料、压缩包、生成内容与补充证据也须绑定角色、方向、可访问对象、完整路径和内容 hash，并有可复核的差异依据。角色来自任务，不凭文件名猜测；新增、删除和二进制同样保留对象证据，未绑定项保持待定。

用实际内容身份覆盖新增、删除和重命名，mtime、统计数量或文件大小不能代替 hash。用户源文件与本次验证产物分开登记；隔离产物也记录路径和身份。交付前复核快照，只对变动影响的证据重新检查。

### 受限输出与隔离

先获得完整路径清单，再分块读取有关内容；截断不当作 EOF。删除、配置、迁移和生成文件追踪到实际发布形态及来源。验证按需要使用隔离环境，只清理自己创建的材料；不默认 checkout、stash、reset 或清空用户文件，也不为绑定版本增加无关执行或生产访问。

<a id="coverage"></a>

## 契约与覆盖记录

每个变更对象（包括删除）关联改变的行为/不变量、真实入口或消费者、规范与需求来源、实现路径及未实现要求。文档对照其描述的实际实现。测试名称、提交消息与目标实现均不能单独定义需求；来源缺失、冲突或消费者不可访问时登记具体缺口，继续其他对象。

把合同逐项标为必须、允许、禁止或未定义，保留限定前提与等价保护。允许后台继续不表示必须继续；允许替代预算保护时，要核实实际保护，不能只因缺少首选计数器确认失效。另一案例的更强合同不自动适用；等价定义或消费者缺失仍是语义缺口。

用一份覆盖记录关联对象、`rule:<ID>`（或补充规则及来源）、状态和证据位置：

| 状态 | 所需记录 |
| --- | --- |
| 已核验，未发现问题 | 可复核观察与证据 |
| 发现问题 | 满足确认门槛的因果证据 |
| 未验证 | 缺失前提、资料或检查 |
| 不适用 | 当前对象未触发规则的理由 |

阶段进度用 `stage:S0`–`stage:S4`，与规则证据状态分开。已读参考、执行检查和来源可合并在此记录，证据按位置或 ID 复用。触发的交叉引用逐条应用；按对象+规则去重引用环，已读标记只防重复加载。细则“完成”表示核验收敛，以缺口结束仍是未验证。所声明范围中的每个对象与触发规则都有状态；发现一个严重问题不能代替其余检查。

<a id="evidence"></a>

## 确认门槛

一项确认问题须同时满足：

1. **适用要求**：来自用户、项目规范或真实消费者的合同，保留版本、限定前提及来源冲突。对必须、允许、禁止和未定义的判断一致。
2. **可达路径**：具体输入/状态能到达问题，沿调用链核实 diff 之外的校验、授权、序列化和其他保护。
3. **变更因果**：问题由这次变化引入、放大、变得可达，或违反本次明确承诺；附近的既有问题不自动归因。
4. **可观察影响**：说明受影响行为和后果，区分源码证明、模拟与真实运行观察。
5. **反证核实**：实际核查能推翻疑点的保护与合同；成立则撤回或收窄，不靠猜测或代理投票补证据。

工具发现只调查一次，未运行不算已排除。代码气味是线索；没有影响或适用规则时只作获请求的建议。未定义的语义不能自行加要求，也不能因表面缺少首选机制忽略合法等价实现。

源码足以证明时直接引用。需要运行时，检查真实不变量和失败路径，采用已授权的最小隔离反例；不执行无关配置、访问生产、秘密或未授权外部写入。版本敏感结论使用匹配版本的权威资料。

<a id="run-records"></a>

## 运行记录与冻结

真实运行记录包含完整入口/argv、cwd、退出码、源版本或 hash，以及实际捕获的工具输出或 stdout/stderr 原文。已有日志可直接引用，无需复制。合并流注明合并，解析计数/JSON 指回原始记录和转换过程；缺少历史输出、时间或遥测时记录缺口，不补造 stderr 或结果。

只有用户要求归档或准备声明冻结时，执行以下顺序：

1. 保存独立持久副本或内容寻址对象；普通工作区、清理会移除的位置或可被覆盖文件不能冒充冻结件。
2. 从保存位置读回，核实字节/hash、可访问位置、实际保存时间和对应源版本。
3. 成功后才声明冻结；失败保持草稿。若承诺可重建生成产物，同时保留必要源快照。

后续修订另存并指回原件，登记哪些证据失效；保留第一次失败观察。丢失原始材料时保留缺口，重新运行或聊天摘要不能替代原件身份。

<a id="report"></a>

## 分类与报告

分别报告项目规范、需求/业务与公共消费者合同、正确性三个轴。Skill 的规则 ID 是核验索引，不是项目规范。各轴使用确认问题、已核验未发现问题、未验证或无适用来源；缺口不写成确认缺陷，某一轴通过也不抵消其他轴的问题。

采用项目优先级定义；没有定义时：

| 级别 | 判据 |
| --- | --- |
| P0 | 已证明广泛、迫近的严重影响，不依赖尚未核实的特殊前提 |
| P1 | 重要且可达的失败 |
| P2 | 范围有限的确认问题，含有依据的非阻断规范违反 |
| P3 | 有证据的低影响问题 |

按实际影响、触发条件和前提定级，置信度与严重程度分开；类别或可能的最坏后果不自动决定 P0。缺陷与规范违反标明类别；获请求的建议另列，等价方案尊重有依据的作者选择，不以个人偏好或完美主义阻断。

每项问题写紧凑标题、类别/轴、优先级、被审查版本的位置、触发条件或违反规则、影响与证据。按根因去重，多轴归属合并说明；定位最小相关修改范围，删除用旧侧，缺失实现定位相关 diff。输出一次并遵守宿主格式。修复建议只给证据直接支持的最小方向，未明确方案时写约束，不扩张授权。

报告包含比较范围、三轴状态、实际检查摘要和剩余缺口。正文以可行动发现为主，检查摘要写入口/证据 ID、结果及结论范围；仅摘录能说明因果或反证的必要输出。完整 argv、版本、退出码和原始输出按[运行记录](#run-records)保留在已有日志或同一证据记录中，正文引用位置；用户要求完整过程时展开对应记录。覆盖记录保持对象与逐规则状态，用证据 ID 复用观察，无需在正文再复制整张记录或逐条成功日志；保留首次失败与未验证项，不以压缩展示缩小核验范围。已有载体足够时直接复用，无需为每步新增文件。

没有确认问题时写“已核验部分未发现问题”，结论限于可核验范围。只有获请求时才给审批建议，并依据项目门槛和实际影响：缺口不一律阻断，改进也不抵消重大问题；建议不授权合并。

示例：目标把省略 limit 的行为由 0 改为 20，若适用合同要求省略时仍为 0，则用对应两版的调用/输出说明影响，建议修复省略值路径。只有显式缺失或边界确实违反合同才报告，不能凭一个案例推广到所有默认值。
