# 变化路由与遗漏处理

S2 必读。先按实际入口、消费者、运行环境和部署产物匹配所有受影响类型，再按改变的不变量选通用风险；目录名只作线索。类型不是互斥选项：Web 服务同时读取 Web 与服务规则，网络 SDK 同时读取 Web 与库规则。类型规则补充通用规则，链接到已有规则的主题复用其证据。

检查以本次变化、项目承诺和可证实的不变量为范围；为核实影响追踪相关消费者和保护，不扩展成产品能力设计。未承诺的能力不要求新增，需求未定义时保留语义缺口。

## F1 未匹配变化

触发：类型或风险表无对应分支，或专项资料不能解释改变的不变量。

必须从真实消费者、项目标准、技术栈匹配版本的官方资料或领域专家提供的契约提取约束，登记补充检查：对象、来源及适用条款/版本、触发、预期、核验方法、完成门槛、反证。源码资料固定 tag/commit，网页资料保留所引版本或核对日期，项目材料引用被审查快照中的位置。自定义规则用 `X-对象-序号`，不得冒充本目录标准。不可读的硬件/专有格式也按此处理。

完成：变化具有可核实的检查或明确未覆盖原因。触发零条规则不等于已检查；缺少资料时继续其他对象，把这部分保留为缺口。

<a id="f2"></a>

## F2 受影响路径与检查预算

触发：审查启动、范围较大或验证代价较高。

必须先完整枚举，再按影响和不确定性排序；高影响路径优先，覆盖范围保持可追溯。先源码、调用链和已有检查，只有未决问题需要运行时才加隔离试验。已有证据可被多个规则引用，不重复执行同一检查；失效判断以内容、输入、工具版本和依赖为准。记录实际读入的参考与执行检查，避免加载未触发专题。

完成：所声明范围全部有状态；达到证据门槛的疑点停止追加无关验证。不能凭主观时间预算跳过对象再称完整，也不能为追求检查数量重复无变化的测试。工具或预算不足时明示剩余对象和风险。

<a id="f3"></a>

## F3 专业证据不足

触发：缺设备、运行平台、数据、编译器、威胁模型、专业要求或领域审查资格。

必须分开记录源码可证明结论、模拟观察、真实环境观察与认证/合规状态。优先收集当前可得事实，只有目标或证据必须由用户补足才询问；不存在的宿主能力不写成已运行。

必须说明缺失前提会影响哪项结论；仅有未覆盖的其他部署环境不使已充分证明的局部源码结论失效。影响当前判断的设备、配置或专业要求缺口保留为未验证，范围限制另列，不能把两者合并成一律阻塞。

完成：报告指出具体未验证前提及下一项能消除缺口的检查。专家签字、硬件时序、辅助技术和法规符合性均不能由通用审查替代。不得为证明结论访问未获授权的生产或敏感数据。
