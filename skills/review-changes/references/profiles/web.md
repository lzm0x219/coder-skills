# Web 与网络

适用版本的 HTTP、浏览器及安全参考见 [来源](../sources.md)。

<a id="w1"></a>

## W1 网络语义与解析一致性

触发：方法、状态码、header、URL、代理、连接或流式消息变化。

必须追踪实际客户端、代理和服务端的解析及缓存行为，核实消息边界、编码、重定向、超时和连接关闭。双端不同解析只有存在可达输入/影响才确认问题；公共契约按 [C2](../checks/contracts.md#c2)、[C3](../checks/contracts.md#c3)。

完成：协议语义与真实消费者一致，或具体解析/响应错误。单个 HTTP mock 不证明代理链；仅框架自动处理的边界引用匹配版本保护。

<a id="w2"></a>

## W2 浏览器安全与会话

触发：cookie、登录、跨源、HTML/脚本、下载、嵌入或浏览器存储。

必须核实浏览器实际发送凭据和信任边界，检查 session 更新/失效、CSRF 前提、CORS/来源检查和注入上下文；秘密与输入追踪按 [T1](../checks/trust.md#t1)、[T3](../checks/trust.md#t3)、[T4](../checks/trust.md#t4)。

完成：受影响浏览器路径有匹配的保护或可达攻击链。CORS 不是所有请求的访问控制；SameSite/CSP 的存在须结合实际版本、配置和执行上下文。不能为未使用 cookie 的入口无依据要求同一 CSRF 机制。

<a id="w3"></a>

## W3 渲染、导航与缓存

触发：SSR/hydration、路由、静态资源、缓存或离线 service worker。

必须核实服务/客户端初始状态和资源版本组合，检查用户/租户切换、旧页面与新资源、导航刷新/深链接和离线更新；界面规则按 [U1](../checks/ui.md#u1)、[U2](../checks/ui.md#u2)、[U5](../checks/ui.md#u5)，数据隔离按 [D1](../checks/state.md#d1)。

完成：支持入口与版本组合有证据。组件单测不能证明直接导航或 hydration；没有 SSR 或离线承诺时相应项不适用，并写理由。
