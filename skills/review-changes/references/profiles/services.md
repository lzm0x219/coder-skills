# 服务与基础设施

消息、分区和容量分别按 [运行可靠性](../checks/reliability.md)、[资源预算](../checks/resources.md) 的触发规则核验。

<a id="i1"></a>

## I1 启动、就绪与排空

触发：启动顺序、进程信号、健康状态、滚动切换或后台任务。

必须核实初始化失败、接流量时点、终止信号、在途任务排空和终止预算；确认跨实例任务归属与重新投递。探针复用 [O3](../checks/observability.md#o3)，任务生命周期复用 [A1](../checks/async.md#a1)、[A5](../checks/async.md#a5)。

完成：服务从启动到终止的受影响阶段符合承诺。截断容器 grace period 与应用 drain 的组合须检查；不能以本地正常退出证明线上排空。

<a id="i2"></a>

## I2 声明配置与实际资源

触发：IaC、网络策略、IAM、存储、容器资源或基础镜像。

必须查看具体变更计划与实际解析配置，核实替换/销毁、默认值、网络暴露、身份范围和持久化归属；权限复用 [T2](../checks/trust.md#t2)，来源复用 [S1](../checks/supply-chain.md#s1)、[S4](../checks/supply-chain.md#s4)。

完成：声明到真实计划有证据及适用权限，或明确未执行的环境检查。格式校验不证明不会重建数据库；审查不授权 apply 或扩大网络访问。

<a id="i3"></a>

## I3 运维兼容与恢复

触发：配置升级、备份、恢复、灾备、跨区域或依赖切换。

必须把部署顺序、回滚承诺、数据版本及运维入口逐项关联；检查恢复凭据、数据完整性和可用恢复点。恢复语义按 [Q4](../checks/reliability.md#q4)，数据迁移按 [D4](../checks/state.md#d4)。

完成：受影响运维路径有证据或具体缺口。演练、真实灾难和 RPO/RTO 推算分开；不将一次开发环境重启当恢复验证。
