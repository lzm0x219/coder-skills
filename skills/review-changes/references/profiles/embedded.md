# 嵌入式与实时

板卡/编译器/RTOS/安全要求须取实际版本资料，入口见 [来源](../sources.md)。

<a id="h1"></a>

## H1 寄存器与硬件协议

触发：MMIO、寄存器、DMA、总线、字节序或驱动。

必须核实板卡修订、寄存器宽度/副作用、时序、对齐、cache coherence 与屏障；中断/DMA 与 CPU 的所有权按实际硬件规则证明。

完成：改变操作符合 datasheet 或有具体违反。volatile 不自动是原子或同步；主机内存模拟不能证明设备总线及 DMA 行为。

<a id="h2"></a>

## H2 实时预算与中断

触发：优先级、ISR、锁、调度、deadline 或周期工作。

必须核实最坏执行/阻塞、优先级反转、ISR 可用 API 和中断嵌套；预算来自声明期限与目标环境。锁按 [Q3](../checks/reliability.md#q3)，算法按 [R1](../checks/resources.md#r1)。

完成：改变路径在目标平台有时序依据，或明确无法证明预算。平均延迟不是最坏期限证明；单元测试不证明实时调度或 watchdog 安全。

<a id="h3"></a>

## H3 固定资源与更新恢复

触发：栈/堆/flash、掉电写入、启动、固件更新或分区。

必须核实链接布局、最大资源使用、写入粒度与掉电窗口，追踪启动校验、更新中断及恢复/回滚承诺；制品身份按 [S4](../checks/supply-chain.md#s4)。

完成：目标产物与故障窗口符合声明约束。host 编译不证明目标布局；模拟掉电只证明所建模型，不代替设备测试。

<a id="h4"></a>

## H4 故障安全与专业标准

触发：控制输出、联锁、保护阈值、故障降级或安全要求。

必须追踪具体 hazard、安全要求、失效状态与诊断覆盖，核实输入失效/传感器异常/重启的输出；找出项目适用标准版本及所需独立审查，不自行发明认证目标。

完成：受影响安全要求有可追溯证据及专业未验证项。一般 code review 不能颁发功能安全/适航等认证；“默认关闭”也只有符合 hazard 分析时才是安全反证。
