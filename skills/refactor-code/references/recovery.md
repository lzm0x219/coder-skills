# 异常与恢复

先保存当前观察、最后通过的切片和失败命令，再按事实选择转移。保持当前工作区；回退只撤销可确认为本次的修改，并核对用户已有编辑仍在。

## 检查失败

| 已核验事实 | 动作 | 返回与前进条件 |
| --- | --- | --- |
| 同一基线、输入及环境可复现相同旧失败 | 保留旧失败记录，核对本次变更与失败路径是否交叉；独立检查目标切片 | 不交叉且切片通过则继续当前状态；交叉但无法排除本次影响则保持待证 |
| 基线通过，当前相同观察失败 | 缩小到最近切片，找出引入差异的修改，修复并重跑目标反例 | S3；受影响检查通过才恢复切片推进 |
| 基线制品与入口可用，当前制品缺文件、路径或导出 | 修复本切片的构建、资源或入口更新，重验从实际制品导入的消费者 | S3；制品和消费者通过才关闭兼容项；源码通过仅覆盖源码 |
| 有失败，但原始结果、环境或触发条件不可比 | 补充基线复跑、受控输入或环境证据；标为待证 | S1；取得可比证据再分类 |
| 修改前因依赖、权限、制品或配置缺失而无法建立基线 | 核对项目恢复方法与授权，恢复可用条件；无法恢复走环境缺失分支 | S1；环境可用并取得基线后继续 |

重试须改变假设、输入、诊断信息或实现。相同命令与条件的失败重复且无新证据时停止盲重试，调查另一可证伪解释；关键依赖不可获得时按阻塞或部分交付退出。

### 保护检查的观察

检查本身可能出错：先对同一检查运行基线与当前实现，核对它是否观察目标行为。依据原契约纠正错误断言时，给出依据并重跑两侧，保留原始失败记录。接受新的行为预期则需要已确认的契约变化；重构后的输出本身不是更新 golden、快照或断言的依据。

## 环境缺失与范围收缩

为缺口列出受影响观察。可继续切片必须在依赖和行为上可独立验证，且不会提前破坏未验证路径的公共入口或状态。明确新的实施边界及剩余工作；范围缩小回 S0 更新目标记录，再在 S1 建立新切片基线。

局部检查的证据只对应局部切片。继续实施或退出的结论按 [完成判断](verification.md#完成判断)选择，保留原目标未完成项及解除条件。

## 工作区变化与证据失效

验证期间出现外部编辑、用户目标变化、构建配置或依赖变化时，先比较变化来源及范围：

- 目标或授权变化 → S0，重新固定范围。用户改为只读或取消修改时，立即按新边界处理；保留当前工作区，后续清理或撤销依据用户指令。
- 基线或环境变化影响兼容观察 → S1，失效对应兼容项；不相关证据保留。
- 目标方案已不能满足职责或入口约束 → S2，更新方案和受影响切片。
- 当前实现新增修改 → S3，重验受影响切片后进入 S4。

多项变化同时发生时，先返回最早受影响状态，重新核对后续切片；不相关证据保留。证据身份按 [兼容账](compatibility.md#兼容账)核对。无法安全分离用户与本次编辑时保持文件，暂停冲突切片，列出冲突位置和需要厘清的意图。

## 中断恢复

保存当前状态、范围与方案、兼容账、最后通过切片、未解决问题和下一步。沿用项目载体；短任务可保留在上下文。

恢复时先核对当前仓库、工作区和环境与记录的差异，再按上一节选择返回状态。已通过且不受变化影响的切片无需重做；状态不明时收集事实，不能从报告文字推定代码已完成。
