# 兼容基线

按入口、消费者和变化路径选择观察。兼容账沿用项目已有格式或上下文。

## 兼容账

每项包含：观察及契约来源、受影响消费者、基线源码状态、输入与运行条件、预期或原结果、检查方法、当前结果和证据状态。源码状态包括用户已有编辑，以工作区差异或必要文件指纹标识；Git HEAD 只标识提交。基线可用原始工作区、只读副本或已核对的制品。

这里的基线是工作区与行为的验证对照；项目已有正式配置基线时，沿用其命名和控制要求。核对两者的依据时，读取 [来源映射](basis.md#w01-精确定位)。

| 状态 | 判定证据 | 使用方式 |
| --- | --- | --- |
| 基线已建立 | 修改前在可比条件下取得观察，检查能区分目标差异 | 可进入该切片实施，仍需最终验证 |
| 已验证 | 当前实现满足契约，前后观察或契约检查及相关消费者证据完整 | 可关闭本项 |
| 旧失败 | 修改前后的同一失败可复现，且本次影响已独立核查 | 保留例外及影响边界，不合并为通过 |
| 待证 | 缺基线、缺环境、结果不可比或未执行 | 标明阻塞的观察，按异常规则处理 |
| 不适用 | 当前变化与该观察无受影响路径，有调用或契约依据 | 记录简短理由后关闭，不能用未知代替不适用 |

每次结果绑定实际源码状态、输入和环境；对齐会影响结果的规模、版本、调度、构建选项与依赖。前后对照分别调用原始与当前实现，保留基线独立性。

检查覆盖已承诺的契约、已发现的受影响消费者和用户要求的运行路径。未获得任意第三方消费者只限定结论范围；若缺失的是本次必要观察或明确要求的环境，则记为待证并处理缺口。

## 观察细则

只选本次受影响分支，将相应观察加入兼容账。

### 公开库、声明与制品

按契约、包导出及实际调用区分稳定入口和实现路径；已承诺的深层导入同样兼容。未知必要消费者记为待证。

从原承诺入口检查导出名、模块路径、签名、泛型约束和可选性，区分类型与运行时导出。保留真实消费者检查；声明变化按解析出的类型和可赋值约束判断，文本相等只说明文本一致。

路径移动同时核验源码和实际制品的导入解析，检查包导出、构建 glob、文件大小写、相对资源定位、动态加载与声明生成。消费者需要的文件必须进入实际制品。

### 数据、错误与副作用

保存字段、缺省、承诺顺序、编码、空值及异常输入的代表性结果与边界反例。

错误观察包含类型、消费者依赖的消息、抛出时机和副作用顺序。通过调用者核对默认值、对象身份与惰性执行是否属于隐含契约。

### 状态与调度

按实例和资源归属检查初始化、缓存寿命、清理及泄漏。覆盖两个实例隔离、同一实例的订阅或请求共享状态、取消前后行为、重复关闭和失败传播；状态移到模块顶层时，用反例检查共享范围。

调度与集合拆分时，对照事件与微任务顺序，固定快照获取时机、投递前成员检查、回调重入、取消再订阅、关闭后的排队任务及异常传播。可控调度用于缩小反例；原生调度或实际运行补充证明执行环境中的行为。两种证据分别记账。

### CLI、应用与服务

检查退出码、输出与交互、持久化副作用、请求响应、配置和资源路径。

### 性能约束

对已明确的复杂度、吞吐、延迟或资源预算，在一致条件下测量。结论对应实际测量输入与环境。

## 无法取得完整证据

待证项走 [异常与恢复](recovery.md)中的对应分支。替代运行、静态分析与样例对照分别标出证明范围；未观察到差异只支持已执行的输入与条件。
