# 验证与交付

## 验证顺序

先检查本切片的消费者与关键反例，再做受影响包的类型和构建检查。触及共享入口、跨包依赖、资源定位或运行集成时验证相应路径；制品检查按 [观察细则](compatibility.md#观察细则)选择。其余检查由未解风险决定。

异步改动使用可控调度或明确的观察事件，而非增加固定 sleep 掩盖时序变化。反例应能区分正确与破坏语义的实现：例如关闭前取消、回调抛错后的清理、重复销毁。必要时运行一个受控错误变体证明检查能捕捉目标风险；不为普通重命名强制变异测试。

比较原始工作区与最终差异，核对用户编辑、授权范围及每项修改所属切片或消费者更新。失败按 [检查失败](recovery.md#检查失败)分类；工作区、范围或环境变化按 [证据失效](recovery.md#工作区变化与证据失效)重新核验。

## 完成判断

按以下状态选择交付结论，范围以 S0 的当前目标为准：

| 结论 | 必须满足的条件 |
| --- | --- |
| 完成 | 目标结构验收达标；所有实施切片、消费者和必要制品已验证；无本次引入的失败；旧失败有不影响本次目标的证据；最终工作区与通过的证据一致 |
| 部分交付 | 已有可独立使用且验证通过的切片，但原目标仍有兼容待证、未实施范围或环境缺口；列出已交付边界与剩余项 |
| 阻塞 | 当前目标无可独立验证的安全切片，或范围、冲突意图、关键环境等条件尚不明确；保留现状，给出解除条件 |
| 分析完成 | 只读请求已交付有依据的结论，或改造候选无合理收益；对应分析目标完成，不表示代码已重构 |

范围收缩时分别报告当前交付范围与原目标剩余项。每个必要兼容项按 [兼容账](compatibility.md#兼容账)关闭或作为例外说明。

未经授权的行为变化、用户编辑丢失、只读越权或虚报验证均不通过；先修正实际问题和报告，再重新核验。证据不足与已发现回归分别说明。

## 交付内容

沿用项目交付格式，给出变化与收益依据、实际命令结果、兼容覆盖、旧失败、缺口和剩余工作。结论按上表选择；静态、替代与实际运行证据分别说明适用范围。
