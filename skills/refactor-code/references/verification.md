# 验证与交付

S4 核验最终结果，S5 依下表选择结论。

## 验证顺序

1. 检查切片消费者与关键反例，再做受影响包的类型/构建检查。
2. 触及共享入口、跨包依赖、资源定位或集成时验证相应路径；制品按[观察细则](compatibility.md#观察细则)选择，其余检查由未解风险决定。
3. 比较原始工作区和最终差异，核对用户编辑、授权及每项修改所属切片/消费者更新。失败按[失败分类](recovery.md#检查失败)，目标/环境/工作区变化按[证据失效](recovery.md#工作区变化与证据失效)处理。

异步检查使用可控调度或明确观察事件。反例应能区分正确与破坏语义的实现，如关闭前取消、抛错后清理、重复销毁；必要时用受控错误变体证明检查能捕捉风险，普通重命名无需强制变异测试。

## 完成判断

以 S0 当前目标为范围，每个必要兼容项按[兼容账](compatibility.md#兼容账)关闭或列例外。

| 结论 | 条件 |
| --- | --- |
| 完成 | 结构验收达标；所有切片、消费者与必要制品已验证；无本次新失败，旧失败有不影响目标的证据；最终工作区与通过证据一致。 |
| 部分交付 | 有可独立使用且通过的切片，原目标仍有待证/未实施/环境缺口；分别列交付边界与剩余项。 |
| 阻塞 | 无可独立验证的安全切片，或关键范围、冲突意图、环境未明；保留现状并给解除条件。 |
| 分析完成 | 只读请求已获有依据结论，或无合理改造收益；仅对应分析目标。 |

未经授权的行为变化、用户编辑丢失、只读越权或虚报验证均不通过；先纠正实际问题和报告再核验。证据不足与确认回归分别列出。

## 交付内容

按项目格式报告变化与收益依据、实际命令/结果、兼容覆盖、旧失败、缺口及剩余工作，选择上表结论。静态、替代与实际运行证据注明各自范围。
