# 模块、目录与依赖

## 从维护摩擦推导职责

找一个真实或用户指定的变化：它需要修改哪些位置、理解哪些内部约定？将应一起变化的知识聚合，将独立变化的策略分离。以领域责任命名，沿用项目术语。

为目标模块明确拥有的数据、不变量、资源以及外部可见操作。模块应隐藏一个有意义的决策；公共兼容入口允许转发，内部新增层需要独立职责。依赖指向稳定契约；同级互相导入时追踪双方实际需要的知识，选择合并同一职责、移动共享规则或传入有界操作。

拆分共享状态时指定单一所有者，以实例或有界操作传递依赖。按兼容账保留对象身份、缓存和异常语义；目录与职责一起设计。

## 目录重设计

1. 从兼容账确认稳定入口、实现路径及直接路径消费者，列出内部模块与生成文件。
2. 给出目标树，每个目录和关键文件有明确职责；说明依赖允许方向。
3. 保持承诺入口可用，按依赖顺序移动实现并更新内部引用；兼容入口可转发。
4. 按项目权威生成入口更新生成文件；路径迁移的观察见 [公开库、声明与制品](compatibility.md#公开库声明与制品)。
5. 按下文的结构证据验收目标布局。

## 去重复与抽象

对照两个实现的兼容账及变化原因，提取被消费者证实相同的不变量。业务差异保留在明确的调用点；语义不同的相似代码分别维护。共享函数只接受当前消费者所需参数。

检查抽取是否移动了验证、日志、I/O 或回调的执行时机；保持一次调用与重复调用的副作用次数。可配置差异使用明确参数或有界操作，避免以大量布尔分支将多个独立职责搬进同一函数。

## 结构证据

将 S0 的变化实例映射到前后需要理解或修改的位置，核对职责是否收敛。其他证据包括循环依赖解除、状态归属明确、业务规则有单一实现、消费者通过稳定入口访问。文件数、行数或 index 层数只作描述；保留测试与依赖信息，用实际变化证据判断收益。

行为测试与用户指定的目录、依赖方向分别验收。新增层未隐藏有意义决策或目标职责未收敛时，回 S2 改方案；用户指定布局有取舍时明确成本，按约定目标验收。
