# 重构代码

在约定的可观察行为边界内改善指定结构。故障修复、功能新增、差异审查和只读机会分析按用户的主要目标处理；点名本 Skill 也保留该边界。

按 S0–S5 推进；每个状态达到完成条件才前进。小改动可以合并动作，完成条件仍适用。证据保存在当前上下文或项目已有载体，无需为每个状态创建文件。

恢复：检查失败、必要基线或环境缺失、工作区或目标变化、中断续做时，读取 [异常与恢复](references/recovery.md)，按事实返回受影响状态。

溯源：核对规则出处、修改本 Skill 规则或评估正式标准符合性时，读取 [来源与规则映射](references/basis.md)。

## S0 固定范围

核对仓库与项目约束，固定目标、范围、非目标、允许的行为变化。记录原始工作区和用户已有编辑；证据身份在 S1 的兼容账中维护。

用一个变化实例或调用证据描述维护摩擦，确定结构验收方式。会改变范围或方案的目标歧义需要澄清，其余证据继续收集。

完成条件：目标仓库、范围、原始工作区和结构验收方式明确，且修改在既有授权内 → S1；只读请求或无合理改造收益已有分析结论 → S5。

## S1 建立兼容基线

从公开入口和实际调用者追踪受影响路径。读取 [兼容核验](references/compatibility.md)，建立兼容账：每个受影响观察都有基线结果、检查方法和证据状态。已有测试漏掉此次可能改变的观察时，补特征测试或前后对照。

修改前运行必要检查，记录原有失败。关键基线或环境缺失时按恢复分支确认可实施范围。

完成条件：当前切片每个必要观察均有可用基线和检查方法，或有不适用依据；待证项已有证据说明不影响当前切片 → S2。

## S2 选定结构方案

模块拆分、目录重设计或共享抽象调整时读取 [结构设计](references/structure.md)。说明目标职责、布局、依赖方向、兼容入口和切片顺序，并对照 S0 的变化实例说明收益。简单重命名只需确定新名称、消费者及路径更新范围。

每个切片关联兼容账中的检查及结构验收方式。用户指定结构作为验收要求；其他布局选择以职责和变化证据说明取舍。混合功能变化单列行为验收，沿用已有方案确认与授权。

完成条件：切片顺序、职责归属、兼容入口和验证路径完整，收益能核验且未决选择不影响实施 → S3；无合理收益已有分析结论 → S5。

## S3 分步实施

一次实施一个可独立验证的切片，同步消费者、构建和资源路径。保持已约定的算法与资源归属，行为观察按兼容账检查；行为变化按单列验收处理。

运行本切片检查并更新兼容账。检查失败或切片以外的工作区变化按恢复分支处理；检查通过才推进下一切片。

完成条件：当前切片实现及相关消费者路径更新完毕，必要检查满足兼容账，用户原有编辑保留 → 下一切片；所有切片完成 → S4。

## S4 核验结果

读取 [验证与交付](references/verification.md)，按验证顺序核对最终工作区、消费者、制品与差异，逐项关闭兼容账。按 S0 的结构验收方式检查收益。

更新受影响文档；后续变化影响已运行检查时，重验对应项并核对最终证据身份。

完成条件：每个兼容项已归类，必要检查无未解决的新失败，结构验收有结论，最终差异与证据一致 → S5；否则按异常分支处理。

## S5 交付

按 [完成判断](references/verification.md#完成判断)选择交付结论，并按该文件的交付内容报告。直接从 S0/S2 进入时，报告分析结论及依据。

完成条件：报告与实际工作区及已取得的证据一致，剩余任务和限制明确 → 结束。写出报告不代表未完成的检查已经通过。
