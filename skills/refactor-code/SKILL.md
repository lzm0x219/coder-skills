# 重构代码

以约定的可观察行为为边界，改善指定结构。混合功能变化单列行为验收；只读机会分析交付有依据的候选。按 S0–S5 推进，小改动可合并动作，但各出口仍须满足。证据沿用上下文或项目载体。

检查失败、基线/环境缺失、目标/工作区变化或中断 → [恢复](references/recovery.md)；核对出处、修改规则或评估标准符合性 → [来源映射](references/basis.md)。

## S0 固定范围

核对仓库与约束，记录目标、范围、非目标、允许行为变化及用户原有编辑。用一个真实变化实例或调用证据描述维护摩擦，确定结构验收方式；会改变范围/方案的歧义先澄清。

出口 → S1：范围、原始工作区与结构验收明确，修改在授权内；只读或无合理收益且已有分析结论 → S5。

## S1 建立兼容基线

从公开入口和实际调用者追踪变化路径，按[兼容基线](references/compatibility.md)建立兼容账。修改前运行必要检查，保留旧失败；已有测试漏掉受影响观察时补特征测试或前后对照。

出口 → S2：当前切片每个必要观察有可用基线和检查方法，或有不适用依据；待证项已有证据说明不影响该切片。缺关键基线/环境 → 恢复分支。

## S2 选定结构方案

模块/目录/共享抽象改造 → 读[结构设计](references/structure.md)，确定职责、目标布局、依赖方向、兼容入口与切片顺序，按 S0 实例说明收益。简单重命名确定新名、消费者和路径更新范围。

每个切片关联兼容检查与结构验收。用户指定布局作为验收要求；其他选择以职责和变化证据说明取舍。沿用已确认方案与授权。

出口 → S3：切片、职责、入口与验证路径完整，收益可核验，未决选择不影响实施；无合理收益已有结论 → S5。

## S3 分步实施

一次实施一个可独立验证的切片，同步消费者、构建与资源路径；保持约定算法、资源归属及兼容观察，单列的新行为按其验收处理。

运行切片检查并更新兼容账，失败或切片外工作区变化按恢复分支处理。

出口 → 下一切片：实现与消费者已更新，必要检查满足兼容账，用户编辑保留；全部切片通过 → S4。

## S4 核验结果

按[验证顺序](references/verification.md#验证顺序)核对最终工作区、消费者、制品与差异，逐项关闭兼容账，验收 S0 的结构收益。更新受影响文档；后续修改使证据失效时只重验对应项。

出口 → S5：兼容项全有归类，必要检查无未解的新失败，结构收益有结论，最终差异与证据一致；否则走恢复分支。

## S5 交付

按[完成判断](references/verification.md#完成判断)选择结论，报告变化、收益依据、实际命令/结果、兼容覆盖与剩余项。直接从 S0/S2 进入时交付分析结论。

出口：报告与实际工作区及证据一致，结论不超出已完成范围。
