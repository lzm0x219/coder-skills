# Coder 总入口

按用户要得到的结果选择主能力，遵从明确点名及项目约束；只读、规划和实施各按已有授权推进。确认入口在当前环境可用后读取并执行：

| 主要目标 | Skill | 边界 |
| --- | --- | --- |
| 审查 PR、提交、分支或未提交差异的正确性、回归与需求符合性 | `review-changes` | 包含契约文件时仍按差异审查；核对实现是否遵守契约属于此目标。 |
| 设计、变更或评估调用者可见的 API 契约本身 | `design-apis` | 契约来自 PR 时也适用。 |
| 修复已有行为的缺陷 | `fix-bugs` | 仅解释原因走只读诊断；新增行为走实现任务。 |
| 在约定行为下调整模块、目录、依赖或合并重复实现 | `refactor-code` | 结构与行为变化分别验收；只读机会分析先交付有依据的候选。 |

另一部分有独立交付对象且确需不同方法时，再增加第二项能力，例如差异审查中另需重新设计契约。文件类型或拆分动作只是路由线索。

没有合适的可用入口时使用常规能力，必要时说明缺口；规划中的候选按未实现处理。关键目标无法推断时补充最小必要问题。

执行到所选工作流的交付条件，报告实际验证与剩余限制；用户只问推荐时，交付选择及依据。
