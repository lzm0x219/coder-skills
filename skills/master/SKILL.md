# Coder 总入口

识别用户要得到的结果、主要工程问题和相关项目约束。用户明确指定专业 Skill 时，遵从其选择。

任务需要专门方法时，从当前环境中实际可用的 Skill 里选择一个主 Skill。只有任务的另一部分确实需要不同能力时，才使用第二个 Skill。项目规划文档中的候选 Skill 不等于已可用的 Skill。

用户要设计、变更或评审调用者可见的 API 契约时，使用已实现的 `design-apis`；仅按既定契约编码或审查现有实现时，按对应任务处理。

用户要修复已有行为的缺陷时，使用 `fix-bugs`；只要求分析原因而不修改，或请求新增行为时，按相应目标处理。

用户的主要目标是在既定行为与兼容约束下调整模块、目录、依赖或消除重复实现时，使用已实现的 `refactor-code`。只分析全仓改善机会先交付有依据的候选；功能新增、故障修复或 API 契约变化不因涉及文件拆分就改走重构。混合任务分别明确结构与行为的验收条件，遵守既有授权。

通过选定的 Skill 继续完成任务。若用户只问推荐哪个 Skill，简要说明选择依据。若没有合适的专业 Skill，用智能体的常规能力处理，并在必要时说明能力缺口。仅在缺少关键信息且无法合理继续时提问。

遵守用户指定的任务范围与授权。根据实际证据报告已完成的工作和验证结果。
