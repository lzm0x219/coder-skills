# 程序接口的设计期交付

适用：目标编程语言已确定，用户要求设计、重设或演进一个**具体**的库、SDK 或框架公开接口。交付的是调用方可依赖的候选契约；设计期的公开声明可以只有类型与签名，不要求实现运行逻辑。概念探索、仅评审现状及语言未定的任务，按任务范围交付模型或评审意见，明确其尚非可实现的语言级接口提案。

## 先确定主契约载体

1. 项目已有公共声明、包入口或 API 定义时，以该载体和真实导入路径为准。只要求设计时，在提案位置保存候选声明或补丁，不让未批准的草案混入已发布导出；用户要求实现时直接修改项目正式源文件。
2. 没有既定载体但目标语言已确定时，创建独立的**候选公开声明**及**消费者调用文件**。选择目标语言可编译或可静态检查的形式，例如 TypeScript 导出的类型与 `declare` 签名、Go 接口/类型、Rust trait/类型或 Python `.pyi`/Protocol；遵循项目实际工具链。代码围栏只能作为阅读副本，不能代替能被工具读取的主契约文件。
   若目标语言无法在无实现的文件中表达某个拟议公开入口，可使用隔离在提案目录、明确不可运行且不会进入发布包的编译占位实现；若不这样做，就把该入口及其消费者静态检查标为未验证。不要为了让声明通过检查而删去任务实际需要的构造器或其他公开能力。
3. 用户只要求讨论设计方向、未确定语言、未提供可写工作区，或明确要求只输出文档时，可在答复中交付签名草图与语义说明，并标明“概念稿，未作语言级验证”。不要为了满足模板另建与任务无关的项目。

## 具体提案的最小证据

- **公开声明：** 包/模块入口、导出、类型、方法、配置、返回值和稳定性边界一致；声明使用的外部类型要有真实依赖或明确的候选适配层。未知领域事实用未决项说明，不用看似确定的类型掩盖。
- **消费者：** 包入口已定时从拟议包入口导入；尚未确定时从候选声明文件导入，并把包导出标为未决。展示一个普通调用和一个关键失败或边界调用；需要资源释放、取消、分页、未知结果或异步完成时，让调用者的处理代码可见。示例中的调用方函数和外部依赖要有可检查的类型，避免靠未声明的自由变量使草图看似成立。
- **语义说明：** 以操作为单位写清类型无法保证的前置条件、缺省/空值、结果、副作用、失败后状态、重试/并发/所有权及服务版本等命中规则。区分已验证既有契约、设计决策和待验证假设；设计期不声称运行正确或已发布。
- **演化证据：** 已发布接口变更时保留旧调用作为消费者，列出源码、行为、传输/持久化及环境兼容结果与迁移路径。新接口说明未来公开承诺从何时开始。

## 验证与结论

1. 在不实现运行逻辑的情况下，先用目标语言现有工具检查公开声明和消费者代码。TypeScript 可对候选声明与正常/失败调用运行 `tsc --noEmit`；其他语言使用对应的编译或静态检查命令。包入口已定时检查该导入路径；只从候选声明文件导入时，类型检查不证明未来包的导出正确。只在有高风险类型混淆时增加必要的拒绝用例，不用大量测试复述声明。
2. 检查类型工具无法证明的语义：正常调用与关键失败是否同文档一致，失败后的资源/远端状态能否处理，命中的 `MUST` 是否指向具体契约值或证据。多个失败可能同时发生时核对错误优先级。类型检查通过不代表服务行为、密码学实现或发布包通过。
3. 报告三个独立状态：**声明/调用静态检查**、**语义走查**、**运行与真实服务验证**。工具缺失、依赖无法取得或未运行时写“未验证”及原因；仍可交付草案，但不能把未验证项写成通过。实现或发布任务继续验证真实包导出、运行示例和旧消费者。

## 设计状态

| 状态 | 判据 |
| --- | --- |
| 草案 / 待验证 | 缺少目标语言的可检查声明或消费者、静态检查失败/不可运行，或对象身份、关键失败恢复等命中 `MUST` 仍未决。可继续评审，但须列出阻断项。 |
| 可供设计评审 | 候选声明与消费者一致，能检查的部分已检查；命中的语义规则有具体行为、证据或明确未决；评审者可以逐项提出或接受取舍。此状态不表示提案获批。 |
| 设计通过 | 阻断性未知已解决，命中的 `MUST` 均有契约依据，公开名称与行为取舍已记录，并由项目的设计决策者接受。此状态不表示运行实现或发布包通过。 |

完成判据：评审者能从主契约文件和消费者代码看出**实际公开形状**，从语义说明判断**每个操作如何使用及如何恢复**，并能区分静态检查、设计判断与真实运行证据。未获设计接受时交付可评审提案，不自行升级为“设计通过”。
