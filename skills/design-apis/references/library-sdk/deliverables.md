# 程序接口的设计期交付

适用：目标语言已确定的具体库、SDK 或框架提案。按[共同交付与核验](../common.md#delivery-evidence)固定合同、消费路径与证据；此页补充语言声明、导入与制品要求。设计期可只有类型和签名；概念、语言未定、仅评审、无可写工作区或只输出文档时，可交付签名草图及语义说明，标为“概念稿，未作语言级验证”。

## 先确定主契约载体

1. 已有公共声明、包入口或 API 定义时，沿用真实载体与导入路径。设计任务保存候选声明或补丁；未批准的草案留在提案位置，获准实现时修改正式源文件。
2. 没有既定载体时，创建目标语言可编译或静态检查的**候选公开声明**及**消费者调用文件**，如 TypeScript 类型与 `declare`、Go 接口/类型、Rust trait/类型或 Python `.pyi`/Protocol。代码围栏只作阅读副本，主契约须能被工具读取。
   语言无法无实现地表达某个入口时，可使用隔离在提案目录、明确不可运行且不进入发布包的编译占位实现；否则将该入口及消费者静态检查标为未验证。声明必须保留任务需要的构造器与公开能力。

## 具体提案的最小证据

- **公开声明：** 包/模块入口、导出、类型、方法、配置、返回值和稳定性边界一致；外部类型须有真实依赖或明确的候选适配层。领域事实按 C02 处理。
- **消费者：** 包入口已定时从拟议包入口导入；否则从候选声明导入，并将包导出标为未决。共同要求中的普通与关键失败调用须展示资源释放、取消、分页、未知结果或异步完成等命中行为；调用方函数与依赖有可检查的类型。
- **语义说明：** 写出类型无法保证的前置条件、缺省/空值、结果、副作用、失败后状态、重试、并发、所有权及服务版本等命中规则，按 C05 核验。
- **演化证据：** 已发布接口保留旧调用，分别列源码、行为、传输/持久化及环境兼容结果与迁移路径；新接口说明公开承诺何时开始。

## 验证与结论

用项目的语言工具检查声明及消费者，例如 TypeScript `tsc --noEmit`；只在高风险类型混淆时增加必要的拒绝用例。包入口已定时检查实际导入；候选文件类型通过只证明该文件，不证明未来包导出。

按[共同核验](../common.md#delivery-evidence)分别报告静态、语义与运行证据。核对同时失败的错误优先级；类型检查不证明服务行为、密码学实现或发布包。实现或发布任务另验真实包导出、运行示例和旧消费者。

按[统一交付判据](../common.md#delivery-status)报告结果：公开声明与调用须显现实际形状，语义说明须让调用方判断使用与恢复。
