# API 设计维度与遗漏检查

适用：已经按 [Skill 入口](../SKILL.md)选择接口类型后，核对设计维度与组合边界；全范围评审时检查遗漏。本页不维护第二份类型路由。每个项目实际采用的格式、传输、语言和提供方都要记录；未列专有协议按一手规范补差异，不能以近似类型直接判定符合。

## 组合边界

按 C03 列公开调用与恢复通道，从入口匹配每条边界；类型页负责具体协议/profile 的触发条件。

内核/驱动、数据库厂商、硬件/GPU、文件格式、浏览器或其他专有接口，按实际调用形态组合以上分支，再取得目标官方规范、平台/version/profile及consumer工具；例如C系统调用需要原生ABI/资源语义，数据库wire protocol需要相应协议规则，不能仅因它是“SDK”而省略。目标没有采用某个protocol时，其专有细节不强制加载。

## 逐维度审查

| 维度 | 所有接口要回答的问题 | 条件下的权威位置 |
| --- | --- | --- |
| 公开身份与领域 | 谁调用什么；旧名称/完整入口/符号/字段身份是否保留；事实还是拟议命名 | [共享审查 C01–C04](common.md)；SDK命名与类型页原生身份。 |
| 数据与编码 | 类型/缺失/null/default/精度/单位/时间/Unicode/unknown/union/schema | [数据 CD01–CD16](common/data.md)，协议codec差异按类型。 |
| 操作与状态 | 成功、失败、副作用、提交/确认/终态及部分成功分别是什么 | C05；HTTP LRO、RPC终态、broker ACK、插件hooks、SQL事务、CLI进程各自规则。 |
| 错误与恢复 | 哪一阶段失败；错误优先级、重试类别与未知结果；消费者下一步 | 类型页；C05的状态走查与消费者反例。 |
| 生命周期与所有权 | 谁持有资源、何时释放、关闭/取消/卸载/删除竞争；bytes与别名 | SDK runtime/原生/扩展；实时关闭；订阅生命周期；query/CLI资源。 |
| 并发与一致性 | 重复、并发、排序、原子性、事务、快照、恢复屏障、reentrancy | 采用机制的类型页；不可把模型推定成部署保证。 |
| 可靠性与流控 | deadline、预算、退避、ACK、投递、cursor、重连、backpressure | HTTP/RPC/事件/Webhook/实时的专有规则。 |
| 安全与权限 | 主体/租户/对象/字段、凭据、签名、外部目标、秘密、业务滥用、认证流程、入口清单及拒绝边界 | [安全 CS01–CS17](common/security.md)，具体认证与协议安全profile。 |
| 成本与限制 | 大小/嵌套/并发/分页/批量/流/存储/解压/CPU/等待是否有界 | CS08和各类型限制；数值来自项目或候选决定，不能编造通用常数。 |
| 兼容与演进 | 每个读写方向、源码/ABI/wire/行为/权限/成本、版本与迁移 | [演进 CE01–CE10](common/evolution.md)及协议/语言差异。 |
| 文档与诊断 | 主契约、消费路径、错误/操作身份、追踪字段、秘密、未决与接受状态 | C06与类型交付页；没有遥测需求不强行引入服务设施。 |
| 工具链与证据 | adopted version；主契约/旧consumer；实际工具验证范围及未验证事项 | [协议交付](protocol-deliverables.md)、[程序交付](library-sdk/deliverables.md)、CLI/query载体。 |

维度表用于发现遗漏，不代替逐条规则核验。命中项按 [C06](common.md#tracking)关联具体合同与证据；评测覆盖记录与设计任务的适用记录分别维护。
