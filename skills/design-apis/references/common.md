# 跨类型契约审查

适用：具体 API 设计、演进与评审。此页维护跨类型要求；执行顺序和类型路由由 [Skill 入口](../SKILL.md)维护，协议差异由命中的类型页维护。

## 规则等级

`MUST` 是命中条件后必须满足的要求；`SHOULD` 是默认推荐，实质偏离记录理由；`MAY` 是可选设计。分别标明协议强制、格式要求、生态建议和 Skill 综合要求，规则数量不作为质量分数。

条件子页未另标等级时，固定合同、失败/恢复与消费证据继承 **Skill MUST**；方案中的“优先”“建议”“避免”继承 **Skill SHOULD**，明确可选项为 **MAY**。子页明确等级优先。外部强制只按采用的协议/profile、版本和原条款生效；生态约束仅在采用对应 profile 时生效。引用来源不将整条设计要求升级为协议 MUST，协议 MUST 也不可用偏离理由豁免。C06 按 ID 记录性质和依据，标题未重复等级不构成免检。

## 固定输入与证据

**C01｜公开契约｜MUST 固定调用者已有依赖。** 记录完整入口/符号、消息与字段身份、成功/失败结果、副作用、可见顺序及稳定性承诺；对照原始事实、主契约和消费者。HTTP 合并 base URL 与 path，二进制/序列化身份另核验。更改时按[演进](common/evolution.md)逐方向判断；未得到实际旧消费者不能称影响范围已查清。

**C02｜设计依据｜MUST 分开事实、候选和未知。** 每个容量、时间窗口、错误映射、权限、重试和兼容承诺注明来源或正式设计决定。已知操作名不推出请求/返回类型、参数签名、完整路径、旧行为或 module/package 配置；缺少原始声明时保留未知。为可编译样例选择的签名须在声明/fixture 及报告中同时标为候选，不能改称真实旧契约。规范没有规定、项目没有确认的数值属于候选；需要决策者接受的关键未知阻断“设计通过”，但可带明确问题提交评审。

新设计中可由设计者提出的行为，MUST 给出有界候选、理由、适用前提及需确认项，不能一律用 TBD/“实现时决定”替代字段含义、状态、错误恢复、安全边界或成本合同。依赖既有事实、真实消费者或外部系统配置的缺项继续保留未知；候选不升级为现有事实。完整候选可供评审，接受与生产验证另记。

**C03｜组合接口｜MUST 标出每条边界。** 识别客户端/服务端、生产者/消费者、host/plugin、进程/线程、租户/提供方；分别列请求、响应、回调、控制、数据和恢复通道。GraphQL over HTTP、SDK over RPC、Webhook 中的事件、CLI 调远端等按组合读对应分支，不能仅验证外壳。

**C04｜规范适用｜MUST 固定采用版本及要求性质。** 一手规范的协议强制、格式要求、生态建议与本 Skill 综合要求分开。记录采用的 profile、版本、章节及项目偏离理由；专有或未列协议先查其权威规范并补覆盖差异，不能将相似协议规则直接套用。资料索引是定位工具，链接存在不证明条款适用。

**C05｜语义走查｜MUST 核对可观察状态变化。** 对每个操作从前置条件追踪至提交/确认/终态和资源释放；错误、取消、超时及部分成功分别确定哪些效果已发生、哪些结果仍未知、调用者下一步。声称“只能修改某字段”时核对公开参数/返回类型和运行边界是否允许改动其余字段；批量各结果分支都须满足逐项覆盖承诺。自写的样例 guard、重试或校验器同样验证正常与拒绝路径；模型证据按其真实层级报告。

<a id="tracking"></a>

**C06｜交付｜MUST 建立规则到产物的追踪。** 从原始需求、适用规则、主契约、正常/边界/失败消费者到工具结果形成链路。逐条记录规则 ID/文件 scope、触发条件、要求性质/等级、采用版本与出处章节、契约位置、证据及未决；等级可按该类型页明确的继承规则判定，但必须区分协议、生态与 Skill 设计要求；未触发说明原因。一个规则区间共用“已考虑/通过”不能代替各行为的证据；顶页概览不替代命中子页。测试期望从需求/契约独立推导，不能照实现当前输出写通过断言；状态前置条件须有绕过负例，身份/幂等作用域须有跨对象碰撞反例。局部样例涉及授权、批量或成本保护时，确认拒绝路径在副作用前且合法路径能执行；尚未实现的机制明确排除在该样例的验证结论之外。具体协议交付见[协议载体](protocol-deliverables.md)，程序接口见[声明和消费者](library-sdk/deliverables.md)，CLI/查询接口见各类型页。

追踪表按规则保留独立状态与契约位置，共享证据、规范出处和验证边界用 ID 定义一次、逐行引用。共享项写清适用 scope、协议/profile、版本、章节与要求性质；行内记录不同等级、例外和未决，继承关系仍可定位。正常/拒绝消费者及工具记录复用同一证据 ID；共同的运行限制集中说明，特有缺口留在对应行。未触发项可合并说明共同原因并列出各 ID，未知仍为未验证。完成条件是每条规则能还原自身触发条件、等级、合同、证据及缺口；共用 ID 不等于共用“通过”结论，沿用已有载体即可。

## 交付与核验

具体提案沿用项目的主契约和工具链，注明权威载体、版本及完整入口；复合接口分别固定两侧与控制/数据面的来源，同一字段保持单一权威。第三方接口的本地消费决策须与提供方契约分开。概念探索、现状评审、语言未定或只输出文档的任务按其范围交付，注明尚未完成的验证。

至少展示一条正常消费路径和一条关键拒绝、失败或兼容路径，写出输入、可见结果、错误标识与下一步；恢复按 C05，既有接口演进加入旧消费者或旧消息。类型/schema 无法表达的权限、副作用、确认点、顺序、幂等、保留期和错误优先级写入语义说明。按 C06 追踪每条适用要求，合同满足条件才关闭对应项。

| 证据层级 | 核验与报告 |
| --- | --- |
| 格式 / 静态 | 用匹配主契约版本的解析器、校验器或编译器检查载体与样例，记录实际工具、版本、命令和通过/拒绝用例；结论限于工具覆盖的格式或类型。工具缺失、依赖不可得或未执行时标为未验证。 |
| 语义走查 | 按 C05 对照需求、主契约、正常/关键失败/旧消费者及报告；自写控制分支须核实正常与拒绝路径。依赖真实提供方、服务、broker 或部署配置的规则注明验证对象与缺口，模型只证明对应模型。 |
| 运行 | 用户要求实现或已有可运行服务/包时，验证真实调用、结果、副作用、拒绝和恢复及新旧消费者；发布任务核验实际制品。设计任务单独列出运行未验证项，其缺失本身不否定完整合同的可评审性。 |

完成条件：调用方能从主契约和消费路径判断如何调用与恢复；命中 MUST 有具体合同，实际检查及未决可定位。设计尚未决定与运行尚未验证分别报告，接受状态按下表判定。

<a id="delivery-status"></a>

## 交付状态

追踪三个独立轴：**合同是否完整**、**消费/运行证据层级**、**外部事实与项目接受**。没有部署证据不表示没有设计；局部测试通过不能掩盖适用规则缺合同。收尾先补齐可设计的关键行为和载体版本矛盾，未知不改称不适用。

| 状态 | 判据 |
| --- | --- |
| 草案 / 待验证 | 主契约或关键消费者缺失，必要格式/静态检查失败或不可执行，或命中关键 MUST 无具体决策；列出阻断项 |
| 可供设计评审 | 主契约与正常/关键失败消费者一致，能执行的检查已执行；具体行为、证据和未决分别可定位，评审者能接受或修改 |
| 设计通过 | 阻断性未知已解决，命中 MUST 有合同依据，命名、兼容和恢复取舍已记录，且项目设计决策者已接受 |

可评审不表示获批；设计通过不表示实现、真实服务或发布部署已验证。报告实际格式/声明静态检查、语义走查、模型或真实运行的范围与限制。概念探索、现状评审或语言未定按任务范围交付，不制造无法核验的代码或空表。

这些步骤是内部设计要求，综合[Google AIP-180](https://google.aip.dev/180)、[OpenAPI 规范](https://spec.openapis.org/oas/v3.1.1.html)及各类型官方契约的兼容/载体模型，不是上述资料逐字规定的通用流程。

## 仅在命中时读取

| 分支 | 规则来源 |
| --- | --- |
| 有可交换的数据、schema、数值/时间/编码或严格解析器 | [数据契约](common/data.md)；格式特有行为再查协议页。 |
| 有跨信任边界、身份、租户、外部 URL、秘密或可滥用成本 | [安全契约](common/security.md)；认证机制与部署实现按项目安全设计确定。 |
| 有已发布调用方、持久化消息、跨版本包/ABI或服务能力变化 | [兼容演进](common/evolution.md)；协议/宿主语言差异再查相应分支。 |

共享页不要求每个任务实现所有机制。纯本地无状态函数也要固定公开输入/结果和实际证据，安全/租户/重投等未触发分支可直接说明不适用。
