# HTTP 集合查询

本页在 API 提供集合列表、检索、跨集合查询或部分表示时读取。AIP-132/158/160/157 属于 Google API 风格示例，只有选择该风格时字段名/语法才成为约束。

**H18｜分页契约｜返回集合且集合可能超过单响应预算时。** 固定默认与最大页大小（来源可为容量测量或产品决策）、无效/负数/超限输入行为、排序键和稳定次序、游标有效期、游标与过滤/排序/父资源绑定方式、集合变更期间的快照或弱一致保证、终止判据。若允许短页或空页而仍有后续数据，消费者必须以明确 continuation token 判定终止；不得让客户端以 `items.length < page_size` 猜测结束。分页 token 是不透明值，不应暴露凭据/内部游标结构；服务端仍需对每页重新授权。token 被篡改或与请求参数不匹配时返回稳定输入/状态错误并提示从首屏重启。若选择 AIP-158 profile，指定 page_size 超最大值时压到最大值、负值报输入错误、page_size 可在续页改变而其他参数不变；其他 profile 明确自己的规则。证据：首/中/末页、空中间页、改变筛选后复用 token、过期/篡改 token、并发插入/删除。参考：[AIP-158](https://google.aip.dev/158)、[Azure API pagination](https://learn.microsoft.com/en-us/azure/architecture/best-practices/api-design#implement-data-pagination-and-filtering)。

**H19｜排序稳定性｜允许 order/sort 时。** 为支持游标续读，排序必须有确定 tie-breaker（通常是稳定资源 ID），并规定空值、时区/精度、大小写和方向语义；若排序字段不唯一，说明服务端如何稳定打破平局。只开放有明确用例和可承受查询代价的字段；未知字段/方向返回可识别的输入错误，不能静默忽略成另一种顺序。排序顺序变化可能破坏游标，需绑定到 cursor 并拒绝不匹配续读。证据：相同排序值、多页边界、未知字段和跨页修改。参考：[AIP-132 ordering](https://google.aip.dev/132#ordering)、[AIP-158](https://google.aip.dev/158)。

**H20｜过滤语言｜允许 filter/search 时。** 定义语法版本、可过滤字段、类型与操作符、布尔优先级、转义/编码、时区/精度、大小/复杂度预算及非法语法处理。把用户提供的值作为数据参数化，而非拼接为下游 SQL/表达式；字段级授权须在过滤前后都保持数据边界，防止过滤器侧信道暴露不可见对象。未知字段或不支持运算符应返回定位到输入的稳定错误；明确空筛选与缺省筛选差别。没有证据时不得照搬 AIP-160 的语法作为所谓通用标准。证据：有效组合、类型不匹配、转义值、越权字段与复杂度拒绝。参考：[AIP-160](https://google.aip.dev/160)、[AIP-132 filtering](https://google.aip.dev/132#filtering)。

**H21｜部分响应｜客户端可选字段投影时。** 定义投影语法与嵌套规则、未知/不可授权字段的响应、必返身份字段、默认完整性，以及投影与分页/缓存/ETag 的互动。若投影可能省略调用方后续所需字段，提供读取完整资源的路径。采用 field mask 时把其放在明确约定的侧通道或请求字段；若选择 AIP-157 profile，mask 参数为可选且显式 `*` 返回完整字段；不能因使用 AIP-157 而让未选字段和值在不同操作中出现含糊。证据：空 mask、`*`、未知字段、受限字段、嵌套重复项及旧消费者。参考：[AIP-157](https://google.aip.dev/157)。

**H22｜总数与聚合｜返回 total/count/facets/aggregates 时。** 说明计算口径是筛选前还是筛选后、精确或估算、与列表快照是否一致、权限过滤是否计入以及成本/新鲜度边界。若无法在分页快照上提供一致总数，标为估算或不返回；不得给出看似精确但基于不同数据窗口的数值。证据：筛选、权限、集合变化前后的小型已知数据集。参考：[AIP-132 total_size](https://google.aip.dev/132#request-message)。
