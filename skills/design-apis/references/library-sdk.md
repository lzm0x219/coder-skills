# 库、SDK 与框架的程序接口

适用：设计或评审公开的包导出、类型、函数、方法、错误、配置及扩展点。先确认目标调用者、项目稳定性承诺和代表性调用场景，再按条件读取下列 reference。SDK 包装远程服务时，程序接口与传输契约分别设计。

## 按任务读取

| 触发条件 | 读取内容 |
| --- | --- |
| 目标语言已确定，需设计具体的库/SDK/框架公开程序接口 | [设计期交付](library-sdk/deliverables.md)：选定契约源、公开声明、消费者调用与设计期验证；只做概念讨论或现状评审时按对应轻量产物。 |
| 新增、重设或调整公共程序接口 | [基础契约](library-sdk/design.md)：调用点、公开表面、领域模型、类型、函数、错误、组合、依赖边界、文档与程序接口安全默认值。 |
| 新增、修改或评审公开名称 | [命名规范](library-sdk/naming.md)：领域词汇、调用点、动词、类型角色、分页/长任务阶段及目标语言惯例。 |
| 接口涉及状态、资源、异步、并发、显著成本或外部依赖 | [运行契约](library-sdk/runtime.md)：只应用命中的条件规则。 |
| SDK 包装远程服务或长任务 | [远程 SDK](library-sdk/remote.md)：客户端、凭据、远端失败、重试、分页、长任务、响应元数据与服务版本。 |
| 发布包跨模块系统、平台、feature 或运行时分发 | [包与平台产物](library-sdk/packaging.md)：exports、入口、声明、条件导出、feature 与支持矩阵。 |
| 公开接口跨 C ABI、FFI、JNI、P/Invoke、Wasm 或其他原生边界 | [原生互操作](library-sdk/native-interop.md)：ABI、内存/句柄所有权、异常/恐慌、回调与目标矩阵。 |
| 框架允许第三方实现接口、继承基类、注册插件或接收回调 | [框架扩展点](library-sdk/extensions.md)：扩展者兼容、钩子顺序、重入、线程、卸载及能力协商。 |
| 修改已发布接口、环境或包产物 | 同时读[兼容与演化](library-sdk/evolution.md)：先固定旧版消费者，再判定影响与迁移。 |
| 评审设计提案或发布候选 | [评审工具](library-sdk/review.md)：反模式、取舍、流程和可复制清单；同时读取被评审接口命中的规则。 |
| 将原则落实到具体编程语言 | [语言映射](library-sdk/languages.md)：用目标语言的官方资料核验适用机制与版本。 |

## 交付完成条件

具体提案按[设计期交付](library-sdk/deliverables.md)提供主契约、公开声明、正常与关键失败消费者和分层验证；未定语言、概念讨论或现状评审按相应任务范围交付。公开入口、稳定性和命中的运行/远程机制均有具体行为，演进保留旧调用及迁移依据。

新增或重命名时执行[命名准入](library-sdk/naming.md#命名评审的完成条件)，区分事实依据、正式取舍与未决。最终按 [C06](common.md#tracking)核对适用规则，以[交付状态](common.md#delivery-status)报告结果。
