# 库、SDK 与框架的程序接口

适用：设计或评审公开的包导出、类型、函数、方法、错误、配置及扩展点。先确认目标调用者、项目稳定性承诺和代表性调用场景，再按条件读取下列 reference。SDK 包装远程服务时，程序接口与传输契约分别设计。

| 触发条件 | 读取内容 |

| 新增、重设或调整公共程序接口 | [基础契约](library-sdk/design.md)：调用点、公开表面、领域模型、类型、函数、错误、组合、扩展、文档与安全默认值。 |

## 交付完成条件

1. 先按[设计期交付](library-sdk/deliverables.md)确定主契约载体及验证层级。具体公开接口提案在目标语言与工具链可用时，提供可检查的公开声明及正常与关键失败消费者调用，并运行静态检查；包入口已定时从该入口导入，尚未确定时从候选声明导入并标记包导出未验证。未能检查时标为未验证，不写作通过。只请求概念讨论、现状评审或未定语言时交付相应结论。
2. 写出公开入口、输入、结果、可见副作用及稳定性级别；调用者无需阅读实现就能判断如何使用。
3. 对命中的运行或远程分支，写出资源归属、关闭/取消、并发与重试等**具体行为**；不适用的机制不制造占位规则。
4. 变更已发布接口时，列出旧调用、拟议调用、各兼容维度和迁移路径；用户要求实现或发布验证时，用旧消费者样例接入候选包并记录结果。
5. 评审结论指向具体规则、调用示例或消费者证据；无法核验的兼容性明确标为未知。
6. 新增或重命名公开入口时，按[命名规范](library-sdk/naming.md)记录候选、事实依据或正式设计取舍，以及结论状态；对象身份不明或取舍尚未作出时交付未决项，不把拟议假设写成已验证的命名结论。

每次只加载命中分支的 reference。
