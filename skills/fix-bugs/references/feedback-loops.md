# 缺陷反馈循环

S1 按症状选择能经过真实故障路径的入口；S4 用同一判据检验根因，S6 复测原始场景。

| 分支 | 操作 | 红灯与可比条件 |
| --- | --- | --- |
| 已有失败测试 | 运行最窄相关测试；仅测内部函数时补用户调用入口。 | 用户可见结果失败；固定输入与断言。 |
| 函数/库/SDK | 相同参数的最小调用夹具。 | 比较返回、错误类别和副作用；固定依赖/版本，退出码不足以说明行为。 |
| CLI/文件处理 | 保存脱敏输入，重跑原命令。 | 语义断言或稳定快照检查输出文件、stdout 与退出码；排除无关时间戳/路径。 |
| HTTP/RPC | 对本地或获准测试实例重放同一请求。 | 固定身份、请求体、初态；检查状态、响应与必要状态变化。 |
| UI | 经实际入口操作，观察 DOM、网络或可见结果；人工操作用下方脚本。 | 保存步骤和观察点；截图只作观察材料。 |
| 线上独有请求/事件 | 在隔离环境回放；不可回放时核对脱敏日志与版本。 | 保留顺序、身份、时间字段，回放隔离生产副作用。 |
| 偶发/竞态 | 在安全夹具同条件采样，再逐项改变并发、延时或顺序。 | 记录失败/总次数、超时与条件，前后可比；改变启动/信号处理时验证原信号仍可达。 |
| 变更后才出现 | 以同一红/绿判据比较好坏版本、配置或数据；足够自动化时二分。 | 每个状态实际运行，区分构建/环境差异。 |
| 性能回退 | 固定用户指标、预算或正常基线，以及输入、机器/配置、预热与采样；重复测中位数、尾部、波动，再用 profiler/查询计划定位。 | 同方案复测，改善超过波动且原始慢场景也改善；单次计时/日志量不足以证明收益。 |
| 输入空间大 | 从真实失败例做属性、生成或差分检查。 | 明确不变量，保存种子和最小反例；原场景仍须最终复测。 |

## 采集与回放

先脱敏凭据与个人数据，凭据通过环境变量或安全存储传入。脱敏抹去信号时记录证据缺口，并索取可安全使用的样本。重复采样只用于无外部副作用的检查；隔离请求、事件和测试初态。

## 未能建立红灯

核对版本、输入、配置、权限、时序与环境，寻找脱敏日志、trace 或请求样本。

- 源码与明确不变量独立证明另一个缺陷：先建立对该不变量变红的检查，再转 S4 核实；原症状保持「未复现」，按有限交付验收。
- 没有红灯也没有独立证据：记录已试入口和缺失证据，停在 S1。

## 人工与采样工具

从 Skill 目录运行：

```sh
bash scripts/hitl-loop.sh "导出时报错" "打开测试环境并登录" "点击导出"
python3 scripts/repro-rate.py --runs 30 --timeout 10 -- <安全且可重复的检查命令>
```

人工脚本逐步等待操作并输出脱敏观察：退出码 1 红、0 绿、3 无法判断、2 输入不完整。

采样前先单独确认检查命令非零确因同一症状，再计数；保存返回值分布以区分检查自身错误。计数器退出码 0 仅表示采样执行成功，`red` 才是检查非零次数。
