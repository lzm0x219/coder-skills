# `coder:fix-bugs` 评测记录

日期：2026-09-30。对象是本仓库的 `skills/fix-bugs/`；插件尚未安装或发布。本记录按 `writing-for-agents` 的入口指针、信息层级与剪枝、完成条件、实操能力、行为证据各 20 分评分。静态校验、受控夹具、真实项目和原报告者场景分别记账。

## 实施与规则

主文件用 S0–S7 明确每步操作、进入下一状态的证据和回退条件。S1 要求先运行能捕捉**用户同一症状**的红灯；S5 要求同一检查旧红新绿；S6 检查原始场景、针对性回归及修复边界的正常行为；S7 区分完整交付和有限交付。若原始输入不可得，替代复现修复且受影响检查通过只能有限交付，原场景保持未知。`references/feedback-loops.md` 按症状给出十种反馈循环及其判红条件，主文件只在需要时指向它。

配套人工复现脚本输出 `RED/1`、`GREEN/0`、`UNKNOWN/3`、输入不完整 `/2`。间歇采样脚本拒绝非有限超时值，中断或超时时清理检查进程组；修复了子进程创建到赋值之间收到信号会漏清理的问题。一次独立时序评测曾采用信号掩码修复，导致被启动程序继承屏蔽的信号；发现后改用延迟处理信号，并新增相邻行为测试。这个失败是评测发现并修复的真实回归，不计作首次通过。

## 独立执行记录

| 类型 | 旧红与结果 | 状态边界 |
| --- | --- | --- |
| 受控确定性错误 | 人工复现输出 `RED` 却退出 0；独立执行修复后 `y/n/u/输入不完整` 分别退出 `1/0/3/2`。S1 参考指针前移后，新的执行者确实读取了参考。 | 同一入口旧红新绿，且检查相邻退出码。 |
| 受控时序错误 | `SIGTERM` 后检查进程继续运行；第一次修复引入信号继承回归，修订规则后新执行者验证子进程仍能处理自身的 `SIGTERM`。主仓库另以确定性夹具固定 `Popen` 窗口缺陷。 | 不能只检查清理；还须检查被修改边界的正常行为。 |
| 未复现报告 | 直接运行 `y` 已退出 1；执行者没有臆造修复，另外验证管道 `| cat` 可将调用方退出码变成 0，保留原调用方式未知。 | 留在 S1，报告缺少的调用命令、日志与版本。 |
| 有限交付 | 用户所述 `RED/0` 无法复现，但同一脚本 `UNKNOWN/0` 可独立证明有错；修为 `UNKNOWN/3`，复测 `y/n/u=1/0/3`，只交付这一行为。 | 原始 `RED/0` 不称已修复。 |
| 只读反例 | 面对只要求解释原因的请求，执行者没有选择修复 Skill，也没有修改文件。 | 入口排除条件生效。 |
| 无提示正例 | 只给隔离夹具中的 `RED/0` 缺陷，没有指定专业 Skill 路径；执行者自行读取仓库内 `fix-bugs`，旧红新绿并核对 `y/n/u=1/0/3` 与语法。它还读取了环境中已有的 `diagnosing-bugs`。 | 证明本仓库情境下可自行找到 Skill；不等于安装后自动发现测试。 |
